# Day1：技术方案与实验约定

日期：2026-10-09。依据「讨论IMDB评论分类细分领域」中的两周安排，用户已授权开始 Day1。

## 目标与范围

题目暂定：**面向 Apple Silicon 的高效电影评论情感分类：领域分词适配与知识蒸馏研究**。
任务是英文文档级情感二分类。目标是准确、推理快、验证表现稳定；不预设领域分词或蒸馏一定有效。

Day1 交付可复现环境、数据审计、固定划分、原配 tokenizer 分析、模型候选和实验协议。
Day2 再完成预训练编码器的小规模训练、数值对照和真实训练预算；Day1 的合成 MLX 验证不能代替它。
Rust 自主流水线安排在 Day3–4；今天通过 Python 调用 Hugging Face 的 Rust 分词引擎，建立输出参照。

## 技术选择与替代路线

| 路线 | 优点 | 代价与结论 |
|---|---|---|
| ModernBERT-base + 原配 tokenizer + MLX | 与长影评和效率研究相符 | 自行适配结构和权重，先验证数值；主模型候选 |
| BERT-base-uncased + 原配 tokenizer + MLX | 有官方 MLX BERT 示例可参考 | 上下文短、架构较旧；兼容性保障 |
| DistilBERT 或教师截层学生 + MLX | 参数更少，适合蒸馏对照 | 仍需实现与数值验证；Day7 前按预算决定 |

不因论文更新就替换已经可靠的基线。ModernBERT 的性能描述来自作者评估，不能直接推定 Mac 上更快。
官方 BERT 示例也不能证明 ModernBERT 已被支持。Day2 若主候选适配受阻，先用 BERT 打通训练链路，并记录原因。
不使用别人已在 IMDB 上微调的完整分类器作为本项目成果。

## 数据流与隔离

官方 tar.gz → 验证 UTF-8、标签、数量、非空 → HTML 换行和实体清理 → 文本哈希分组 → 分层划分 → JSONL 与 SHA-256 清单。

- 官方训练 25,000 条，划为训练 22,500 条、验证 2,500 条，各类别各占一半，seed=42。
- 相同清理文本放在同侧；标签冲突组整体留在训练集，数量公开，不自动改标签。
- 官方测试 25,000 条保留。仅检查完整性和原有重复，不根据测试内容调整划分、词表、长度或模型。
- 官方训练与测试若有原生重复，记录而不静默删除。正式结果必须注明这一局限。
- 不引入额外 50,000 条无标签数据，后续若使用，单独建立实验条件。
- 清理仅替换 `<br>`、解码 HTML 实体、折叠空白；保留否定词、大小写、标点。BERT 的小写化由原配 tokenizer 自身负责。
- JSONL 的 id、哈希、标签是审计元数据，模型输入只能取 text，禁止将文件名中的评分输入模型。
- 精确文本分组不解决近重复或同电影相关性，不声称验证集完全独立同分布或无一切泄漏。

## 最小实验矩阵

| ID | 编码器/学生 | 分词器 | 训练条件 | 用途 |
|---|---|---|---|---|
| B0 | BERT-base | 原配 | 标签微调 | 兼容性和准确率基线 |
| M0 | ModernBERT-base | 原配 | 标签微调 | 主候选 |
| M1 | 与 M0 相同 | 仅用训练划分适配 | embedding 适配 + 标签微调 | 分词适配对照 |
| S0 | 同一小学生结构 | 学生原配 | 标签微调 | 蒸馏必要对照 |
| S1 | 与 S0 相同 | 与 S0 相同 | 标签 + 教师软目标 | 蒸馏收益 |

长度先探测 256/512，主候选通过预算后才加 1024。BERT/DistilBERT 不直接使用超出结构限制的 1024。
长度试验先用同一模型比较，避免把架构、输入长度和词表变化混为一个改进。
M1 若替换 token ID，必须同步映射 embedding；若增词，必须扩展 embedding 并记录初始化及适配预算。
词表训练只读 train，validation 仅用于评估，test 完全隔离。分词更短本身不构成准确率提升证据。
若预算不足，第6天冻结一个主要改进；JEPA、强化学习暂不进入必做矩阵。

## 训练、评估与记录协议

- 主指标 Accuracy、Macro-F1；记录混淆矩阵、训练/验证损失、训练/验证差距。
- Day2 先探测 batch 4/8、长度256/512和浮点精度，记录每步耗时、峰值内存与完整 epoch 估算。
- 初始微调候选：AdamW、学习率 2e-5、weight decay 0.01、最多3 epoch、warmup 10%；这些是待验证起点，尚未获得实验支持。
- 按每个 epoch 的验证 Macro-F1 选择 checkpoint，连续2次无改善早停；平局按较低验证损失。
- 最终候选在同一数据划分上用42/43/44训练种子复验，报告均值与标准差，不重新划验证集。
- 第11天冻结模型与超参数后正式测试，禁止据此返回调参。
- 推理分别记录分词、模型、端到端耗时；模型计时必须 `mx.eval` 同步，排除下载、冷启动与预热。
- 单条延迟报告 p50/p95，批量吞吐量和峰值内存独立报告；相同数据、batch、长度与精度下比较。
- 今天 tokenizer 单遍吞吐量只作探索，不作为正式系统延迟结果。
- 后续实验记录配置、数据哈希、tokenizer revision、依赖版本、随机种子、检查点及设备。

## 验证与失败处理

数据验证检查类别数量、评分范围、唯一 ID、非空文本、UTF-8 与训练/验证哈希无交集。
下载先落 `.part`，完整 tar 可读后再改名；保留归档哈希以便复现，不将本地计算的哈希误称为官方校验值。
tokenizer 首次解析远端 revision 后锁定 commit 和文件哈希，后续重跑沿用锁定版本；数据变动会拒绝分析。
MLX smoke 使用合成数据检查 GPU、自动求导、参数更新、有限梯度、损失下降及保存加载一致性。
网络或 Metal 权限失败应明确报告；不能用假数据或 CPU 计时冒充正式 GPU 结果。
