# Laya-CE 语义候选受控重采样对照设计

本文件承接用户批准的“原训练分区筛选 → 受控重采样设计”。候选审阅与暴露计划演算已完成；当前池规模有限，暂不启动正式训练。原始数据、标签及划分不修改；校准和验证错题不进入梯度训练。

## 推荐对照

以 warmup=0.05、label_smoothing=0.05、两轮 CE、seed=43 为共同配置，原前缀 512 总 tokens、FP32、batch=8、累积=1；控制组沿用原全量逐轮 shuffle，处理组仅改变经语义复核的候选暴露次数。两组均从同一上游原始权重开始，不从诊断用已训练权重续训。首尾窗口暂不混入该训练因素。两组新 run_id，正式训练前完成配对冒烟；旧组合权重只作为历史参考，不替代新适配器的同时期控制。

## 三种选择与取舍

1. 推荐固定次数替换：候选在两轮中总共多出现一次，非候选中同标签样本各少出现一次；保留两轮全部原 ID 的至少一次覆盖，预算精确可审计。
2. 通用 weighted replacement：实现直观，但重抽整个池即使全权重为 1 也只覆盖部分样本，会额外改变控制组的覆盖，故不用于本对照。
3. 直接追加难例：保留普通样本暴露，但增加更新与算力，不满足本轮固定更新数要求。

## 固定次数替换的精确定义

候选必须为原 22100 gradient IDs 的子集；经全文及可见前缀复核，存在目标语义、原标签与整体态度一致、至少一个模型判断错；标签张力、仅因尾部截断而错和明显噪声独立隔离。模型分数为已见训练样本的排序依据，不声称折外难度或无偏泛化。

按原标签分别处理。对候选排序后用独立 `random.Random(seed)` 打乱，将前 ceil(H_label/2) 条安排在第一轮额外一次，其余第二轮额外一次；每条候选两轮总暴露为 3，控制组为 2，即固定 1.5 倍。每轮内单条最多出现两次。

对同标签非候选用独立 `random.Random(seed+1000003)` 排序后打乱，选 H_label 条作为替换位置，按两轮额外数分配；两轮移除的非候选 ID 互不重复。相应位置替换为候选，再调用上游原 seed+epoch shuffle。每条被替换非候选两轮仍出现一次，其余两次，不重复移除同一非候选。如果 H_label 大于非候选数则拒绝该方案。

每轮仍为负类 11065、正类 11035、总数 22100；micro-batch=8、grad_accum=1 时每轮 2763 次优化更新，两轮 5526 次。两轮总样本暴露 44200 不变；候选额外暴露 H 次，其他样本相应减少 H 次。报告 H/44200、候选正负分布及各语义类型，明确小池带来的处理强度有限，不承诺目标准确率收益。

使用独立 Python RNG，不改变上游 option-order RNG 或 Torch RNG 的取样次数。样本内容与批内长度的变化仍可能改变 dropout 路径，不声称两模型随机轨迹完全相同。不得仅为了类别配额补入未经确认的语义样本，也不改标签。

## 实现与准入

冻结候选清单包含 ID、原标签、正文 SHA、语义分类、模型分歧/错误证据、审阅证据与排除理由。保存所有原 ID 两轮暴露计划及每轮有序输入 ID SHA，核验候选确实 3 次、被替换非候选 1 次、其余 2 次，且两轮联合覆盖全部 22100 条。

训练适配器只包裹上游逐轮 epoch_items 来源。必须固定并核验上游 train_model 实现哈希，拒绝不支持的循环调用方式；控制模式必须与原路径参数、随机数状态和数值结果一致。保持非有限值保护、原 warmup 调度、优化器状态和 epoch_checkpoints 机制。小规模双轮 CUDA 审计确认所有梯度/权重有限、更新数与暴露计数正确，再启动正式配对。

逐轮保存 epoch-001、epoch-002，记录损失和 SHA；训练结束后独立进程对每轮/最终保存权重完整评估 2500 开发样本，主比较预先固定为最终两轮 Accuracy；NLL、ECE、正负类混淆矩阵和配对修正/回退为辅助。最佳轮次仅作诊断，不能看结果临时换主比较。若有净收益，再用同一候选清单做 seed=42 配对复验，不重新按该种子的验证错题筛候选。

## 冻结的初步候选与执行状态

共审阅原训练分区 136 条，初步候选 28 条（负类 9、正类 19）。多标签语义计数为褒贬混合 17、评价对象 7、低质量但喜欢 17、反讽 5；同条可以属于多个类型。审阅由单个 AI 会话完成，未经过独立人工标注，不能视作已证实的无噪声训练池。

候选证据清单为 `reports/laya-train-hardcase-mining-v1/combined-review/pilot-candidates.json`，SHA-256：`9a9efb63b7f085532004e9c7fb63cd94de8a4a9901531a5870890a0ba6d0aa9a`。该哈希仅冻结本轮初步清单；扩池需另存版本，不覆盖此清单。

固定次数替换已完成纯 ID 演算：候选 28 条各暴露 3 次，另 28 条同标签非候选各 1 次，其余 22044 条各 2 次；两轮覆盖全部 22100 IDs、总暴露 44200、总更新 5526，每轮类别计数不变。完整逐轮有序 ID 与 SHA、逐 ID 计数保存在同目录 `resampling-exposure-plan.json` 和 `exposure-counts.csv`。该演算不是训练适配器，也没有执行优化器更新；适配器和 CUDA 配对冒烟仍是正式执行前的必要检查。

本轮决定：暂不开展付费正式配对训练。额外暴露仅占 28/44200 = 0.06335%，目标类型覆盖有限，而且单会话语义复核仍有主观性。直接得到“无改善”也难以区分方案无效和处理强度过低，不能据此宣称受控重采样无效。下一步优先审阅已导出的 87 条未命中关键词的训练分歧样本，避免继续依赖关键词代理；必要时再设计原训练分区内的折外难度证据，并评估计算预算。不得为了增大处理强度随意提高倍数或加入标签张力样本。

已有 seed=43 基线/组合配对与 epoch-001、epoch-002 检查点保留，本轮没有新增训练。未来正式配对仍严格按上述 seed=43、两轮、相同初始化/更新预算、逐轮检查点协议执行。每组既有约 44 分钟仅作粗略排程参考，实际耗时和余额需重新核验。
