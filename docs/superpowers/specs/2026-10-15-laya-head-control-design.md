# L2 同期头部训练对照设计

日期：2026-10-15。状态：**设计已整理，待用户审阅；训练入口尚未实现，正式训练尚未启动。** 本轮承接用户对“设计同预训练初始化、同输入的 L2 对照”的授权。无 worktree，不切分支，不提交 Git，不使用视觉伴侣。

## 1. 要回答的问题

在同一份 Laya 发布编码器权重、同一输入、同一训练预算下，从新初始化开始，原 Laya 决策头与共享线性头各自联合微调编码器，两者的开发 Accuracy 相差多少，差值在三个配对 seed 上是否同向？

这项比较估计**指定初始化与训练协议下，整套头部的贡献**。它不单独分解 Transformer、类型嵌入和非线性 scorer 的贡献，也不估计每种头调到各自最佳超参数后的性能上限。

现有 L1 的原始编码器探针为 96.68%，完整模型为 96.84%，差 −0.16 pp，固定权重下的配对样本 95% 区间为 [−0.48, +0.16] pp。该编码器已与原头在 IMDB 上共同适配，不能替代本次联合重训。见 [L1 报告](../../../reports/laya-frozen-probe-baseline-s43-mps-fp32-20261015-v1/REPORT.md)。

## 2. 方案比较与推荐

| 方案 | 能回答的问题 | 主要代价或限制 |
| --- | --- | --- |
| **推荐：同发布编码器，原头与线性头都重新初始化，配对重训** | 给定训练协议下的头部结构比较 | 六次完整训练；原头也要重新学习，不能当成原历史基线复现 |
| 保留发布的原头，对比新初始化线性头 | 实际换头后的综合得失 | 混合头部结构与预训练头权重优势，不能单独归因于结构 |
| 冻结已有 IMDB 编码器，再训练读出 | 已有表示能否被简单读出 | 已由 L1 回答；不能识别联合微调时的头部贡献 |

本设计采用第一项。第二项若以后执行，应作为独立的实用对照另立协议，不在看到本轮结果后追加成“更公平”的主比较。

## 3. 相同初始化的准确含义

来源为 `configs/laya_model_lock.json` 锁定的 `convaiinnovations/laya`，revision 为 `7b928d828b7b0e022f929d9bd2e44165aa270148`。发布权重 SHA-256：

```text
891102d372688fc2a094dac56a384bc537b87c63f21f9f3dac0be2b7cbc8d86c
```

每次运行只复制其中 `encoder.*` 参数与必要缓冲区，转为 FP32；六次运行的编码器初始状态必须逐 tensor 相同，并给出规范化状态哈希。不得从 baseline-s43 等已在 IMDB 上微调的权重起步。

发布文件中的 421,293,827 个参数元素为 FP16，另外 3 个温度缓冲元素为 FP32；转 FP32 不恢复发布前已经损失的精度，两组共享相同的量化起点。

**这里是 Laya 发布编码器，不是未经 Laya 训练的原始 `answerdotai/ModernBERT-large`。** 发布配置记录已有 7,313 次更新，编码器已与 Laya 决策头共同适配。保持这个起点符合本项目内的头部对照，但结论不能外推为“原始 ModernBERT 不需要 Laya 头”。原始 ModernBERT、ModernBERT-base、普通 pooled 分类输入均属于其他比较。

原头与线性头均不读取发布权重中的 `head.*`、`type_emb.*`、`scorer.*`、`act_head.*` 或温度值。源资产加载前后核验 SHA，不运行会自动修写源 tokenizer 配置的加载路径。

## 4. 两个条件的结构

两组编码器 hidden_size 均为 1,024，候选位置来自同一 `marker_pos`；都输出按当前槽位排列的两个 logits，由同一 softmax CE 训练。

### 4.1 `original`：新初始化的原 Laya 决策头

保持上游 `DecisionModel` 的 logits 路径：类型嵌入 → 两层 Transformer head → 按 marker 取候选向量 → LayerNorm、Linear(1024,1024)、GELU、Linear(1024,1) 共享 scorer。Transformer 的 16 个注意力头、4,096 中间维度、norm_first、dropout 0.1 及动态注意力实现均沿用锁定版本。

采用上游正常构造器的默认初始化，包括 `TransformerEncoder` 复制初始层的行为；不另对两层随机重置。训练前保存初始化规则、随机状态和各模块状态哈希。这里的“原头”指原架构，不指保留发布的头权重。

### 4.2 `linear`：共享线性候选 scorer

直接取编码器的两个 marker 表示 `h_s`，使用共享的 `Linear(1024,1,bias=False)`：

```text
logit_s = w @ h_s
positive_margin = w @ (h_positive - h_negative)
```

不添加类型嵌入、Transformer head、LayerNorm、池化、额外 dropout 或槽位专属偏置。共享 scorer 的公共偏置会在 softmax 中抵消，因此显式去掉。线性层使用 PyTorch 默认的权重初始化。

与 L1 相比，这里联合微调编码器，且没有 L1 差向量读出的独立截距；不能将两者分数差全部归因为编码器训练。

### 4.3 参数与接口

| 模块 | `original` 可训练参数 | `linear` 可训练参数 |
| --- | ---: | ---: |
| 同源编码器 | 394,781,696 | 394,781,696 |
| Transformer head | 25,192,448 | 0 |
| 类型嵌入 | 3,072 | 0 |
| scorer | 1,052,673 | 1,024 |
| 合计 | 421,029,889 | 394,782,720 |

源权重还有 263,938 个 action head 参数和 3 个温度缓冲元素。两组 CE 训练均不包含 action 分支；温度在训练后单独拟合，不进入优化器。参数数目来自源 safetensors 的形状审计；新构造器实现后必须再次逐模块核对。

单独实现明确标注 `head_kind` 和版本号的 CE 包装器及加载器，不将新线性 checkpoint 冒充为可由未修改 `laya.load` 或现有 MLX 入口直接加载的原结构。

## 5. 固定数据与输入

沿用原 22,500 条训练来源，其中 22,100 条参加梯度训练，400 条仅作温度校准，2,500 条为开发验证。以既有 baseline-s43 manifest 的 ID 顺序和 `calib_seed=42` 核对分区；三个训练 seed 均不改变分区。原标签保持不变，不纳入 94 条共同错题的自动改标、重采样或语义改写。

| 文件 | SHA-256 |
| --- | --- |
| `data/processed/train.jsonl` | `f39b1e522d3d6375a5f7fc6c254ec3cb2795f956774f09086c6fd755f747acd7` |
| `data/processed/validation.jsonl` | `dbc3205038851d78e3e31ec5e5985005bfc0b53854371bed7eb9c03f764d2094` |

两组训练、校准和开发评估全部使用 `head_tail`：512 总 token，192 head 上限，原问题与选项文本不变，评论最多 466 token；长评论直接选择原 token 的首 233 与尾 233，不解码重编码。短评论保留原输入。字面 `[MASK]` 的处理沿用现有输入构造，必须恰有两个有效候选 marker。

训练保留 `shuffle_options=["choice"]`：使用上游独立 Python RNG，按 seed 和实际遍历顺序决定选项排列，并同步置换 target。配对两组每个 epoch 的 ID 顺序、选项排列、实际 input IDs、marker、qtype 与 target 必须逐项相同；顺序哈希相同只是审计摘要，底层记录保留供复查。校准与开发固定 negative、positive 顺序，平分时预测 negative。

这个协议与历史“前缀训练、首尾推理”不同，也改变了原头初始化。因此历史 96.84% 只作背景，不作同期控制，不将新结果与它的差值称为头部效应。

## 6. 训练预算与随机性

| 项目 | 两组共同设定 |
| --- | --- |
| 配对 seed | 42、43、44，全部执行，不按中间成绩停止 |
| epochs | 2，无早停；主 checkpoint 固定第二轮结束 |
| micro_batch / grad_accum | 8 / 1，最后一个 batch 为 4 条 |
| 每轮曝光 / 更新 | 22,100 条 / 2,763 次 |
| 每次运行 / 六次总更新 | 5,526 / 33,156 次 |
| 六次总梯度样本曝光 | 265,200 次，不含准入试跑和评估 |
| loss | soft CE；label_smoothing=0 |
| optimizer | 上游 AdamW 分组；encoder_lr=2.5e-5，head_lr=1e-4 |
| AdamW 其他参数 | betas=(0.9,0.999)，eps=1e-8，weight_decay=0.01；沿用对组内全部参数衰减的规则 |
| 学习率 | 原上游 cosine，min_lr=1e-6，warmup_ratio=0 |
| gradient clipping | 全部可训练参数的总范数裁剪 1.0 |
| 精度与检查点 | CUDA FP32，AMP=False，编码器非重入梯度检查点开启；原头沿用其检查点路径 |
| 正式运行次序 | s42 original→linear，s43 linear→original，s44 original→linear |

两组使用同一学习率规则，估计共同预算下的结构效果；不按开发成绩给某一组追加学习率搜索或训练轮数。相同更新数不代表相同 FLOPs、训练时间或显存，成本必须实测。

头部在 CPU 上、独立且恢复外部 RNG 的上下文中初始化，初始化 seed 固定为 `1000003 + training_seed`，构造顺序按各条件的定义固定。进入训练时仍按上游 `torch.manual_seed(training_seed)` 重置 Torch RNG。新头首次构造的随机性必须发生在此显式初始化上下文内，不能依赖加载器碰巧消耗多少 RNG。

上游样本打乱和选项排列已使用独立 Python RNG，不受头部 Torch RNG 消耗影响。锁定编码器的 attention、embedding、MLP 和 classifier dropout 均为 0，准入时断言其值及实际模块配置；无需为假设的编码器 dropout 改写训练循环。原头自身的 dropout 属于其结构，两组不要求消耗相同数量的 Torch 随机数。每组自身的独立进程重复性另行检查。

严格运行时复用现有 `laya_runtime.py`：在 Torch CUDA 初始化前设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，启用确定性算法并禁止 warn_only，关闭 cuDNN benchmark。保留 `cuda_numerics.py` 的 loss、梯度和更新后参数有限值保护，任何非有限值立即停止。

确定性设置不等于完整精度设置。L2 新入口还要显式关闭 CUDA 矩阵乘法和 cuDNN 的 TF32，记录实际后端精度配置，不把“参数为 FP32”当成所有内核均采用完整 FP32 的证据；这项设置同时用于两组，不修改历史运行的定义。

## 7. 保存、校准与开发集开放顺序

1. 核验源资产、代码和锁定依赖，保存六份配置及共同执行协议的哈希；此时不解析开发集正文。
2. 运行 CPU 结构检查与 CUDA 准入；两种头分别完成同条件独立进程复验，通过后才执行正式训练。
3. 按固定次序完成六次训练。每次保留 epoch-001、epoch-002 的 **FP32** 状态；第二轮为唯一主模型，不按校准或开发 Accuracy 换轮次。
4. 在独立进程重载实际 FP32 主权重，验证参数逐 tensor 相等、校准 logits/类别一致，然后仅用 400 条校准集拟合一个温度。记录参数、数值诊断及所有产物哈希。
5. 六次训练、重载和温度拟合全部完成后，写出共同冻结清单；此后才读取 2,500 条开发正文，并在每个冻结模型上评估一次。第一轮 checkpoint 只存档，不新增开发评估或择优。
6. 收齐六组预测后做预定比较；保留失败和超时记录，不以完成子集冒充完整实验。

上游 `save_checkpoint` 会无条件转 FP16，不能直接用于主保存。L2 需独立 FP32 保存和严格重载路径；FP16、MLX 转换如需评估，另作后续部署实验。保存时模型处于 eval，不能在保存过程中改变训练 RNG。唯一状态文件可由 epoch-002 和 final 元数据共同引用，避免重复保存相同大权重。

温度只作用于两个 logits 的差，不继承发布 checkpoint 的温度或分桶配置。用 CPU float64 最小化 400 条的二分类 NLL，限制 `T∈[0.5,5]`。以 `alpha=1/T∈[0.2,2]` 表达凸目标，检查两端导数并执行 80 次二分；全部 margin 为零时取 T=1。保存未校准和校准结果及边界命中情况，不拟合截距、拒答阈值或融合。正温度不会改变 Accuracy。

官方测试在此前研究中已经评估过，不能再当作未使用的确认集。本轮不读取其正文、预测或逐条错误，不用测试选择任何 L2 设置；开发集本身已有大量历史复用，报告仍标为探索性。

## 8. 报告与不确定性

主效应方向固定为 `original Accuracy − linear Accuracy`，单位 pp。先逐 seed 报两组 correct/count、Accuracy、配对差、修正与退化数，再报两组 Accuracy 的均值、样本标准差，以及三个配对差的均值、样本标准差、范围和留一 seed 均值范围。平均准确率不等于平均概率的集成，不生成新的融合候选。

全体、截断与未截断三层分别报告；长短组按原评论 token 数是否超过 466 划分，不按模型置信度或误差划分。已有同分区记录对应梯度 3,436 / 22,100、校准 66 / 400、开发 407 / 2,500 条截断；实现后按同一输入规则复算，不把旧计数当作新运行审计完成。

不确定性分开处理：

- **固定模型的样本变化**：逐 seed 给出 Wilson Accuracy 区间、名义精确 McNemar，以及按真实标签分层的配对 bootstrap 95% 区间。固定 10,000 次、seed=20261015；所有六个预测列使用相同重采样 ID，再计算平均配对差，保留 seed 间对同一难例的相关性。主样本区间有条件于这六个已训练模型。
- **训练 seed 变化**：报告三个实际配对差及上述描述统计。三对不足以可靠估计训练分布尾部；不把 7,500 个“seed×样本”当作独立样本，不用条件样本区间替代跨 seed 区间，也不以三个点的 bootstrap 伪装稳定的总体训练置信区间。
- **仍未覆盖的来源**：校准温度估计、历史开发集选择、源模型预训练适配、标签歧义和分布迁移。概率指标的区间固定已拟合温度，不包含重拟合校准带来的变化。

三个 seed 即使全部同向，在无零差值且用对称符号翻转检验时，最小双侧 p 也只有 2/8=0.25。因此不承诺用本轮证明跨 seed 显著；截断分层和逐 seed 检验也不作多重比较后的同时保证。

同时给出 Macro-F1、AUROC、未校准 / 校准 NLL、Brier 和 15 等宽分箱 ECE；这些是辅助诊断，不反过来改变主 checkpoint 或主要准确率结论。

**不预设非劣效结论，不因差值区间包含零写成等价。** 本轮的投入参考设为 0.20 pp（每 2,500 条约 5 条），它是研究决策尺度，不是噪声地板或统计显著门槛：若原头在三对中均更好且均值至少 +0.20 pp，可优先细分其贡献；若线性头三对均更好且平均优势至少 0.20 pp，可优先评估简化部署；其余情况报告方向不一致或差异小、证据不足。任何情况都不自动部署、追加 seed 或修改论文结论。

## 9. 实现边界与准入项目

现有 `train_laya.py` 的窗口验证绑定 seed42、strict CUDA 和 warmup＋平滑配方，不能通过改 run_id 直接执行本实验。新增独立 L2 入口、结构模块和严格的配置校验，复用上游训练循环、原 token 视图算法、严格运行时和有限值保护。不要为 L2 放宽历史入口的验证条件。

| 部件 | 职责与验收 |
| --- | --- |
| 头部构造 / 加载模块 | 从同源 encoder 构造两种 CE 模型；显式、可重放初始化；严格检查参数数目与结构版本；FP32 保存重载 |
| 输入与配对审计 | 固定 ID 分区与首尾输入；训练中记录实际顺序、选项与输入哈希；逐条拒绝配对差异 |
| 单次训练入口 | 新 run_id 拒绝覆盖；固定更新预算；记录 LR、loss、梯度、RNG 与参数审计；不读取开发正文 |
| 六次编排与冻结 | 固定顺序、失败即停、超时限额；所有模型与温度冻结后才开放开发评估 |
| 汇总器 | 保持 ID 对齐；输出分层、每个 seed 和均值差；区分条件样本不确定性与 seed 变化 |

有意义的 CPU 检查包括：两组初始 encoder 完全相同；原头包装器与上游同权重 logits 和梯度一致；线性公式与实际 forward 一致；候选反序正确重映射 target / 输出（检查槽位映射，不要求改变输入后的预测不变）；改变标签不改变输入；配对 ID/输入差异和非有限值被拒绝；两种结构 FP32 保存重载逐 tensor 相同。短程训练必须实证 encoder 和相应头都有梯度及更新，action 分支不存在于优化器。

CUDA 准入对每个条件用固定梯度分区内的 128 条（按原顺序各标签取前 64 条），运行两轮、32 更新；在独立进程原样重复一次，共四次短程训练。仅用梯度 / 校准来源，禁止读开发正文。逐条件核对两次的实际输入与更新数、每步 loss / 梯度摘要 / 参数哈希及保存重载一致。原头与线性头之间只要求输入和预算相同，不要求梯度或权重相同。

低训练或校准 Accuracy 本身是待报告结果，不触发重新抽 seed 或改参数。非有限值、输入不配对、源 SHA 不匹配、更新缺失、保存重载不一致、确定性错误或资源超限才是停止条件。任一设计或代码实质变化须先更新新协议及 run_id，再重新完成受影响准入。

## 10. 算力与分阶段执行
