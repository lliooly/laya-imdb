# Laya 下一轮损失函数对照与权重交付设计

## 1. 目标与已知边界

继续提高 Laya-CE 的全覆盖开发 Accuracy，再将有效改动迁移到 ModernBERT-base / Laya-RLCD。98% 是研究目标，当前没有证据保证达到。

L1 / L2 已完成。L2 原始头相对线性头的三种子平均差仅 +0.0267 pp，方向不一致；没有支持继续扩大决策头的稳定证据。94 条训练共同错题主要为监督目标冲突或不确定项，不能整体作为语言能力难例重采样，也不能直接改标。

本轮新增 [损失集中度分析](../../../reports/laya-training-loss-diagnosis-20261015-v1/REPORT.md)：94 条仅占训练池 0.4253%，却占旧 baseline-s43 末期未平滑 CE 损失的 80.4000%。它是样本内、同 seed、前缀输入快照，提示一个值得测试的方向，不证明训练噪声是性能瓶颈。

上轮 12 份正式权重本地为 0 / 12；预测、报告和哈希无法恢复权重。用户已报告远端资源不可用，本设计不连接旧服务器、不自动租用资源，也不依赖取回旧 L2 权重。

## 2. 三条路线与优先级

| 路线 | 可回答的问题 | 代价与风险 | 本轮安排 |
| --- | --- | --- | --- |
| 保留 CE 下限的鲁棒损失 | 降低模型强烈抵触原标签样本的相对梯度，能否改善全覆盖 Accuracy？ | 原标签不变，额外前向开销小；仍可能损害真实困难样本 | **推荐作为下一项单因素训练对照** |
| 折外预测与独立复核 | 共同错误是否可跨未见训练样本的模型重现，是否涉及评分与文字目标差异？ | 完整折外 Laya 需要多次训练；独立语义复核还需要另一个审阅来源 | 保留为后续数据诊断，不以当前同 seed 样本内预测替代 |
| 机制化语义增广 | 对象切换、反讽或全局反转的明确能力缺口，能否通过有效对照学习？ | 当前仅少量可见错误候选，旧小池增强无稳定收益；生成标签需验证 | 先补证据，暂不扩大训练池 |

推荐第一条是预算和可检验性选择，不是其收益已获证实。复杂结构、窗口随机化、旧小池重采样和损失参数网格不与本轮叠加。

## 3. 文献位置与候选定义

[GCE，NeurIPS 2018](https://papers.nips.cc/paper/2018/file/f2925f97bc13ad2852a7a551802feea0-Paper.pdf) 定义 `Lq=(1-p_y^q)/q`，在鲁棒性与可学习性之间取舍；原文采用过 `q=0.7`，不能据此认定它适合 IMDB。[Confident Learning，JAIR 2021](https://arxiv.org/abs/1911.00068) 是识别、计数和处理标签问题的另一条已有路线。本轮不估计噪声转移矩阵，不把 94 条筛选写成已完成的 Confident Learning。

两个训练臂：

- **CE 控制**：`L=-log(p_y)`，保持既有零标签平滑设置。
- **混合候选**：`L=0.5*(-log(p_y))+0.5*(1-p_y^0.7)/0.7`，按样本均值聚合。

`p_y` 来自两个实际候选槽的 softmax，`y` 必须随原训练选项置换正确映射。计算使用稳定 log-softmax / expm1，不用后处理温度参与训练，不按批次重新归一化样本权重。相对同 logits 的 CE 梯度，候选乘数为 `0.5+0.5*p_y^0.7`，下限 0.5。

选择混合而非纯 GCE 的理由：旧快照中，7 条可见模型错误候选的纯 GCE 梯度因子中位数低至 0.00209，甚至低于 58 条冲突候选的 0.00903。保留 CE 份额只限制过强抑制，不会识别哪些标签正确。

`q=0.7` 来自已有文献的固定先验，混合比例 0.5 是保守约束；两者均在正式训练前固定，不搜索或根据单次开发结果调整。该候选属于已有鲁棒损失的工程评估，**不声明为针对 Laya 的原创方法**；论文原创性仍需另有机制和比较证据。损失变化也改变整体梯度尺度，测到收益不能单独归因为解决标签噪声。

## 4. 固定实验协议

| 项目 | 固定设置 |
| --- | --- |
| 数据 | 原 22100 梯度训练、400 校准、2500 开发 ID 和原标签；核验原 manifest / 数据 SHA |
| 初始化 | 两臂同一发布版 Laya 编码器；同 seed 的原始两层决策头均重新初始化，起始状态 SHA 完全一致 |
| 结构与输入 | 原始头；固定首尾 512 总 token / 466 评论预算，前 233 + 后 233；原 choice 置换规则 |
| 优化 | 2 epochs；micro-batch 8；累积 1；每模型 5526 次实际更新 |
| 学习率等 | 编码器 2.5e-5、头 1e-4、min_lr 1e-6、weight_decay 0.01、clip 1.0；沿用旧 L2 的调度与优化器，不另加 warmup |
| 数值 | CUDA FP32、AMP / TF32 关闭、strict 确定性设置、非有限值保护、原梯度检查点策略 |
| 种子 | 42、43、44，严格配对；42：CE→混合；43：混合→CE；44：CE→混合 |
| 选模 | 固定 epoch-002；不按开发集挑 epoch、种子或损失参数 |
| 校准 | 每模型独立重载后，仅在原 400 条拟合正温度；温度不改变 Accuracy |
| 开发评估 | 六个模型全部冻结且本地交付通过后，统一评估原 2500 条 |
| 官方测试 | 已被历史正式实验评估，本轮不读取正文或预测，不重新测试，不按历史测试差距扣分调参 |

旧 L2 的 CE 权重不可用，且新 runner / 损失接入需要同期验证，因此三个 CE 控制也重新训练，不能仅拿旧开发分数当控制。保持 94 条在原训练分区，不新增人工权重、改标、删样本或定向采样。

每臂分别保存完整输入 ID / token / 选项顺序审计及更新日志；同 seed 的实际输入流 SHA 必须一致。损失函数不能引入额外随机数。所有新代码、配置和报告使用新协议及新 run_id，不改写旧 source-bound 实验。

## 5. 报告与继续判据

主指标为三个配对种子的 `Accuracy(混合)-Accuracy(CE)` 均值，统一以 pp 报告。完整报告必须同时给出每 seed、样本修正 / 退化数、精确 McNemar、差值标准差、范围和留一种子均值。

对六个固定模型，以共同开发 ID、按原标签分层配对 bootstrap 10000 次，随机种子 20261015，报告均值差的条件样本 95% 区间。明确它不覆盖训练种子总体、开发集历史复用或校准重拟合不确定性。三个种子的双侧符号翻转最小可能 p 为 0.25，不报告成有充分统计功效的跨种子显著性检验。

继续投入的预设参考：均值至少 +0.20 pp、至少 2 / 3 配对方向为正、任一种子下降不超过 0.20 pp。该参考仅决定是否值得新增确认实验，**不等于统计显著或可以部署**。同时展示区间是否包含 0 和 ±0.20 pp；方向混杂或区间宽时明确结论未定。不在本轮自动追加种子或调参；无收益则如实报告这一固定配置未达继续条件。

强制单报截断与非截断组、NLL / ECE / Brier、训练时间与峰值显存。两臂训练目标数值不可直接比较；另报共同未平滑 CE 诊断。94 条四类工作队列可做训练侧描述，但它们是样本内诊断，不用于选模。禁止用 46 条六模型共同开发错误定向产生训练数据。

## 6. 权重交付必须控制训练进度

不能再以“远端有 checkpoint”“报告已下载”或“有 SHA”作为完成依据。每个 epoch 的文件保存完成后，训练进程停在回调内，等待本地接收端签回与本次 run / epoch / 清单 SHA 绑定的验证收据；未收到合法收据不得进入下一 epoch、下一模型或正式开发评估。

每个 epoch 的最小交付包：

1. 完整 FP32 权重、编码器配置、头部结构与初始化元数据；不能只存 adapter、差分或预测。
2. tokenizer 及特殊符号配置，按内容 SHA 复用本地已验证副本；发布模型锁、源代码快照、环境锁及训练配置。
3. manifest、实际输入流、更新日志、epoch 记录及大小 / SHA 清单。epoch-001 另存优化器、调度器、CPU / CUDA / Python / NumPy 随机状态、已完成步数和数据游标，供恢复到下一 epoch。
4. epoch-002 的交付后，继续生成独立重载证据、400 条参考预测及校准温度，并追加本地冻结收据。最终 epoch 无后续训练，不要求为其另存优化器恢复包。

交付分两级，避免循环依赖：**epoch 收据**验证权重 / 配置 / 审计及 epoch-001 恢复状态，允许继续训练；**最终冻结收据**另要求独立重载、校准结果全部交付，允许启动下一模型。所有模型的最终冻结收据齐全，才允许统一开发评估。

本地接收使用 SSH / SFTP 等已授权连接，文件先写 `.partial`，完整 SHA 与大小匹配后原子改名；清单限制为本次输出目录中的常规文件，防止误取其他文件。断点续传必须验证已有块或重算前缀，不能仅相信长度。接收端持久化文件和收据后才发送确认，重复请求幂等处理。

本地独立进程以 CPU strict load 检查权重全部有限、FP32、结构可重建和 state SHA 一致。远端仍按同 CUDA 运行时在独立进程核对参考 logits。文件交付不能改变训练 RNG；恢复包必须通过连续训练与中断恢复的后续更新对照。

故障策略：单次传输最多尝试 3 次；持续失败写 `blocked_delivery`，停止后续更新，保持已保存文件并退出编排，不自动开始下一模型。本地磁盘满、SHA 不符、加载失败、超时、接收端消失、确认丢失，均不得视为成功。不自动删除远端权重、不自动释放实例；恢复仅从已核验状态继续，配置变化需新 run_id。已收到并持久化的 epoch 收据可在重启后重发，不重复训练已完成 epoch。

这一协议降低已完成 epoch 的交付风险，无法保证远端在第一个 epoch 完成前故障时零损失；epoch 中途的进度仍可能丢失。不能承诺任何资源回收场景下绝不丢数据。

## 7. 实现边界、准入和验收

实现拆为三个小单元：损失计算与梯度审计、本地接收与清单验证、等待收据的实验编排。用新脚本组合现有通用加载 / 数据逻辑，不修改旧 L2 绑定源码。方法实现与交付机制先在本地验证，再接入下一台可用 CUDA 主机。

本地验收：

- 固定 logits 对照公式，数值 / 自动微分核验混合梯度等于 `(0.5+0.5*p^0.7)*CE梯度`；覆盖极端 logits、选项置换和无效标签。
- 小模型真实文件传输与加载；注入断线、损坏、缺文件、错误 SHA、磁盘写入失败、过期收据、确认丢失及重复接收。均核对不能越过门禁，不以 mock 成功替代实际字节校验。
- 两 epoch 小模型验证 epoch-001 恢复后输入、RNG、学习率、参数与不中断训练一致；禁止把只含模型参数的检查点叫作可恢复训练状态。
- 检查旧绑定源码 SHA 未变，历史协议仍可审计。权重 / 原文 / 本地环境保持忽略，不提交秘密凭据。

CUDA 准入：两种损失各做两次 32-update 真实短跑，比较各臂内部的重现性；同 seed 起始 SHA 和输入流一致，梯度有限且非零；实际模型经过交付门禁、本地严格加载及独立远端重载。不同损失训练后的参数应不同，不要求跨臂 checkpoint 相等。准入不读开发或官方测试。

只有以上检查通过，且运行前已确认当前服务器、磁盘空间、接收端和传输带宽，才冻结新协议并启动正式六次训练。设计批准和本地测试通过都不代表已获得可用远端资源。

## 8. 预算与交付完成的定义

按上一轮原始头进程约 42 分钟 / 模型估算，六次约 4.2 小时，加 CUDA 准入约 16 分钟；新损失和交付门禁尚未实测，因此只是计算时间参照。

421029889 个 FP32 参数约 1.57 GiB / 模型。12 个 epoch 权重约 18.82 GiB；另加 6 个 epoch-001 Adam 状态约 18.82 GiB，合计约 37.64 GiB，再加配置、审计和公共资产。实际大小以清单为准；两端正式准入均要求至少 100 GiB 空闲，并预先传输一份实际大小文件测量端到端耗时。

串行交付会增加 GPU 等待时间。仅 37.64 GiB 在持续有效 10 MiB/s 下约需 64 分钟，1 MiB/s 下约需 10.7 小时；还没有计入落盘、哈希和本地加载，不能再只按训练时间估租用时长。带宽不足时先报告成本，不悄悄跳过交付门禁。

最终完成条件为：六份最终可加载模型和逐轮权重实际在本地、所有交付清单通过、校准与统一开发结果齐全、完整分析报告写出。分别记录“训练完成”“交付完成”“分析完成”，任何一项缺失都不得统称全部完成。

本次文档与缓存分析不消耗云 GPU；下一步先实现并验证本地损失和交付门禁，再准备有资源时的正式训练。
