# Laya-CE 双前向一致性对照

用户已授权按推荐自主改进、上传平台并训练。本轮沿用原始预训练起点、冻结划分、种子 42、两轮、FP32、micro-batch 8、梯度累积 1、5% warmup 与标签平滑 0.05，只增加 R-Drop alpha=1。官方测试集继续封存。

组合基线开发验证 Accuracy 为 96.44%，89 条错误中 70 条未截断、19 条截断。相对原 CUDA 参照纠正 34 条、退步 20 条，配对精确双侧 p=0.0759；单种子增幅不能表述为稳定收益。历史整体最佳仍为 Mac 96.96%。

可选路线：重复种子确认收益；修改长文本截断；双前向一致性正则化。选择第三项作为新的单因素探索，因为当前截断错误没有改善且主要错误仍在未截断样本。dropout 波动是待检验假设，不作为已确认故障。方法来源：[R-Drop, NeurIPS 2021](https://arxiv.org/abs/2106.14448)，不表述为原创方法。

## 数学与边界

同一编码批次、相同选项顺序，进行两次独立随机前向，不重置随机种子。L = (CE(z1,y)+CE(z2,y))/2 + alpha*(KL(p1||p2)+KL(p2||p1))/2。KL 对有效选项求和，再对样本求平均；忽略 padding 选项。两支都保留完整梯度，不能 detach 任意一支，也不能用平均 logits 代替平均 CE。标签平滑只对梯度训练目标生效。

新增独立 `laya_rdrop.py`；仅在训练循环期间临时接管 `_forward` 与 `soft_ce_loss`，保留上游批次构造、选项打乱、累积窗口、优化器、裁剪、调度和检查点回调。alpha=0 严格走旧路径，不多调用前向或消耗随机数。仅支持 soft-ce；验证/校准/保存权重推理仍为单前向，模型结构不变。所有临时函数在异常后恢复，未消费的成对 logits 触发错误，避免批次错配。

保留 CUDA loss/梯度/参数非有限保护，额外检查包含 KL 的总损失。每批记录 CE 与 KL 汇总到新 run 的 `rdrop_diagnostics.json`；这只表示训练循环状态，完整完成以 run status 和保存权重验证为准。

## 验证与预算

CPU 检验实际 KL 数值及双支梯度、padding、相同分布零 KL、alpha=0 参数轨迹一致、真实上游训练循环的两倍前向及相同 optimizer 更新数、异常恢复、第二支非有限保护、拒绝 RLCD。CUDA 冒烟使用正式 micro-batch 8 和 grad_accum 1，128 条源样本、16 条校准、32 条验证、两轮，28 次更新（warmup 2 次），检查显存、数值和保存后重载。GPU 冒烟通过且下一阶段余额时间足够，才开始正式训练。

预计正式两轮约 85–90 分钟、1.8 元；训练硬超时 120 分钟，完整验证硬超时 5 分钟。预算从用户 2026-10-11 13:26 左右剩余约 7 元按 1.24 元/小时计算，包含开发和空闲时间，启动前重新记录估算余额并预留 5 分钟。不自动追加第二个 alpha 或其他搜索；失败停止，不覆盖任何历史 run，不自动关闭用户机器。
