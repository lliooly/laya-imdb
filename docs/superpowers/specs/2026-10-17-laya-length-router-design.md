# 按长度选择 512 / 2048 模型

用户提出“长的样本走 2048，短样本都 512”。本轮落实为固定规则选择器，并使用已经严格交付的逐条预测离线核算；不重新训练、不调用 GPU、不修改默认部署。

## 规则与实现范围

使用冻结 Laya tokenizer 的完整 review token 数，沿用去除 MASK 文本的既有预处理；不以字符数判断，不先截断后计数。完整模板额外占 46 token：review 长度 <=466 使用 512 模型，>466 使用 2048 模型。超过 2002 review tokens 仍走 2048，并沿用原首尾输入规则，不宣称所有可能输入都可完整容纳。

两边固定为 `laya-context-pair-s42-modal-20261016-v1` 的 seed 42、第 2 epoch 模型。选择器先计算长度、按分支组成子批，再调用对应预测回调并恢复原始顺序；每条样本只进入一个模型。回调按顺序返回有限的两类 logits；空分支不调用。token 长度必须为非负整数。

提供可复用的选择器函数及命令行缓存分析脚本。部署接入时，预测回调负责加载对应权重和按原协议编码，不在本轮切换产品默认模型。CPU 合成测试验证边界、乱序回填、只调用所属分支和无效输入拒绝。

## 离线评估

读取本轮两模型的 400 校准 / 2500 开发预测、冻结摘要及两份最终模型元数据。检查完整交付凭据、样本顺序 / 标签 / 长度一致、互斥数据划分、logits 有限，以及预测文件与封存包的文件大小 / SHA。绑定本次源码和输入哈希到新报告，不修改原实验封存包。

不搜索阈值，不拟合分类路由器。原始概率由路由所选 logits 得到；主校准概率使用各分支原已在 400 校准样本上冻结的温度，先对该分支 logits 除温度再选择，不在开发集拟合参数。报告整体 / 固定分组指标、相对两参照的精确配对 McNemar、条件配对 bootstrap 区间与 Wilson 区间，保存按样本的分支及预测审计。

该方案在观察原分组结果后提出，属于事后探索；2500 条开发集已多轮使用且仅一个 seed。即使条件样本区间有利，也不能据此宣称独立测试或跨种子稳定改善。官方测试数据和预测不读取。

## 成本与验证

只核算分支样本数量、单样本模型调用数、两份模型权重的存储 / 同驻内存下限。本轮不测 GPU / Mac 延迟、吞吐或峰值内存，不用训练耗时推断推理收益。常驻两模型可减少切换开销但需容纳两份权重；顺序装载可减少常驻权重但有装载开销。

所有产物使用新目录 `reports/laya-length-router-20261017-v1/`。保持旧源码 / 模型 / 封存报告不变，不新建 worktree、不切分支、不追加训练或云端资源。
