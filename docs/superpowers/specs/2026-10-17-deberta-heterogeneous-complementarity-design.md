# DeBERTa-v3-large 与冻结 Laya 主融合：单模型互补验证设计

日期：2026-10-17。状态：设计待用户审查，未实施、未调用 GPU、未预留新账目。用户提出转向异构模型；本规格将其收敛为一个新底座、一个固定训练配方、一个固定融合方案的实验。

## 研究问题与边界

研究问题：从不同预训练模型初始化的 DeBERTa-v3-large，能否纠正冻结 Laya 主融合的部分错误，并通过固定概率平均获得净收益？本轮验证互补性，不预设会提升 0.4～0.8 pp，也不将历史 96.4%～96.9% 称为物理上限。

数据修订实验为 96.32%→96.40%，配对 p=0.883，尚未检出稳定收益，不能以此断言标签清洗已证实有效。不同架构、分词器及分类方式同时变化，本轮是完整异构模型方案比较，不是只更换编码器的严格因果消融。

本机缓存重新计数：冻结主融合在 2500 条开发集上答对 2424 条，错 76 条；它与已训练 2048 模型共同错 63 条，其中完整输入组 56 条、原 Laya 截断组 7 条。“70 多条共错”不是本轮准确的分母。76 条主融合错误用于主要互补诊断，63 条共同错误另列，不以这些样本选择训练数据或调参。

## 可选方案与推荐

1. **推荐：原始数据训练一个 DeBERTa。** 保持原始 22100 梯度训练 ID、400 校准 ID 和 2500 开发 ID，检验异构方案是否互补；便于与历史冻结主融合比较，节省一次数据版本选择。
2. 用户修订 v2 训练一个 DeBERTa：可直接使用人工修订，但异构变化与 61 条翻标、3 条删除相叠加，不能隔离来源；目前没有稳定收益证据支持优先选择它。
3. 原始版与修订版各训练一个 DeBERTa：能多回答数据效果问题，但计算、存储与比较数量增加，不纳入本轮预算。

本规格固定采用方案 1。原始数据、修订 v1/v2、已有权重和冻结融合均保持，未经新授权不增加第二个 DeBERTa、新种子、RoBERTa、DAPT、伪标签或融合权重搜索。

## 模型、输入与训练

- 模型来源 `microsoft/deberta-v3-large`，采用标准二分类头，标签 0=neg、1=pos。从官方预训练编码器初始化，分类头按 seed42 初始化；不使用来源不明的 IMDB 微调权重。实施时先解析并冻结实际 commit、配置、分词器、权重文件 SHA；未冻结不得提交 GPU。
- 官方配置为 24 层、hidden size1024、最大位置512。官方卡给出约304M非嵌入参数及131M嵌入参数，不能当作304M总参数估算显存。
- 使用该模型自己的分词器，单条输入总长上限512，含必要特殊 token；超长文本按 review-token 首尾拼接，训练、校准与开发一致。通过 tokenizer 接口实际计算特殊 token 开销，剩余预算前半向上取整、后半取其余；不足窗口时保留全文。
- 不套用 Laya 的46 token模板或强行使用466作为 DeBERTa文本预算。不同分词器的 token 数不可逐条视为同一长度；报告同时保存 DeBERTa长度/截断标记及原 Laya固定分组。
- 一个 seed42，固定两轮、固定最终 epoch2；不根据开发分数早停或选择轮次。原始训练22100条，不使用校准或开发样本做梯度更新。
- 严格 CUDA FP32，AMP/TF32关闭，梯度检查点开启，动态补齐；微批8、梯度累积4，有效批量最多32，最后不足32的一组按实际样本数归一化。每轮691次优化更新，两轮1382次，样本暴露44200。
- 固定全模型学习率1e−5，AdamW betas=(0.9,0.999)、eps=1e−6、weight decay0.01（bias及归一化参数不衰减），全局梯度裁剪1；总优化步数的6%预热（向上取整83步），其后线性降至0；无标签平滑、无鲁棒损失和额外增强。该配置是预声明起点，不声称是该模型在IMDB的最优配方。
- 对损失、梯度、范数和更新后参数做非有限值保护；有限性失败立即停止并保留诊断，不静默更换精度、批量或学习率。

与 Laya 历史配方的学习率、优化步数、分词和分类头不同，因此不将差值解读为“纯架构效应”。固定每条训练样本两次暴露，以一次有边界的合理微调检验该方案的互补价值。

## 工程准入与预算

先完成本地数据成员、标签映射、首尾边界、累积最后一组归一化、断点恢复和交付校验的必要检查。依赖使用新隔离且锁定的环境，验证模型实际需要的 SentencePiece等依赖；不改写现有 Laya锁文件或绑定源码。新版源文件与输入配置使用新 run_id 和 SHA。

GPU短跑只用梯度训练集：固定代表性输入及最长输入测显存、有限梯度和真实更新耗时；最长压力不能代替代表性吞吐。保存临时模型及优化器/RNG，在独立进程严格重载，并核对连续更新与保存恢复后更新的等价性。临时短跑权重不作为正式训练起点。先测短跑检查点持久化和本地小包下载链路，正式各轮仍执行完整验收。

使用单张L40S、4CPU、32GiB，预占式执行，无区域溢价、无自动重试，串行作业。按当前官方基价计算此资源组合约2.40美元/小时，本轮用3美元/小时作为资源组合的保守计算费率。GPU总计费窗口上限90分钟（包括短跑、加载、训练、评估及GPU阶段保存校验）；其外另留0.50美元用于CPU协调、构建、下载和收尾，新增预算总上限5美元。非预占GPU等3倍计价选项不在授权配置内。

最后确认的10美元已为上轮预留4美元，旧账中其余6美元未用于该轮；本轮拟从这6美元内最多预留5美元，保留1美元账面余量。这是基于已知本项目活动的保守额度分配，不是实时账单余额；若出现账户其他消费、价格变化或可用余额不足，须重新缩减或停止，不能挪用现金付费。

短跑至多占15分钟；根据代表性吞吐和最长输入开销估算两轮、模型重载保存与2900条校准/开发评估的余量，只有全部能保守落在剩余窗口内才进入正式训练。估算不通过则停止并报告，不能以减少轮数、切小模型、换BF16或多申请预算暗中变更方案。现阶段不提供未经短跑验证的完成时间承诺。

在提交前将统一资源费率、绝对截止时间、CPU协调和构建阶段的独立时间/成本上限写入新预算与配置并核算；5美元必须涵盖所有新增阶段，不能把CPU路径排除后仍称其为总成本上限。任何阶段无法给出上述保守上界时，不提交该阶段。

## 保存、回传与恢复

每轮保存完整FP32权重、分类头、分词器、模型配置、AdamW/调度器、Python/NumPy/CPU/CUDA RNG、数据及更新位置、源码/依赖锁和manifest。先临时目录写入、封存哈希、原子发布，再提交持久化Modal Volume；独立进程严格加载，验收后才能继续下一轮。

本机接收器使用已经验证的异步下载与分块续传方式，每个整文件SHA验证；两轮权重在本机独立CPU严格重载并用训练集参考logits核对。云端持久化成功与本机已回传分别记收据，只有本机全部通过才标记 `verified_local`。

网络或客户端中断不能删除云端资产；下载可在GPU停止后继续，接收器不得创建GPU。GPU期限到时停止，保留已封存的最近边界；是否恢复需明确预算，禁止自动新增计算。最终可复现交付包含epoch1、epoch2与评估包，不只交预测或云端路径。

## 冻结后的评估顺序

1. 固定epoch2先封存，校验完整训练次数和数据隔离，再读取400条原校准样本拟合单温度（范围0.5～5）；不得用开发标签拟合温度或融合系数。
2. 对2500开发样本做一次前向，保存ID、原标签、logits、两种分词器的长度信息，逐条核对历史缓存ID和标签。
3. 首先输出DeBERTa与冻结主融合的错误互补矩阵：共同正确、主融合独对、DeBERTa独对、共同错误；特别报告原76条错误修复数、主融合原正确样本新增错误数，以及63条旧共错集合中的修复数。该矩阵为诊断，标签知情的oracle上界不能作为可部署成绩。
4. 不论矩阵是否好看，均离线报告唯一预声明融合：**原冻结主融合概率50% + 独立校准后的DeBERTa概率50%**。原主融合内部权重、温度和窗口门控保持；不扫描新权重或选择性只发表有利结果。二分类正概率严格大于0.5预测pos，等于0.5归neg，与历史统计一致。
5. 主比较为固定50:50融合相对冻结主融合（96.96%），同时完整报告DeBERTa单模型；97.00%等权历史辅助、近期修订Laya及其他路由不参加本轮融合候选筛选。

指标：整体及原Laya长度分组的Accuracy、正确数、Macro-F1、AUROC、原始/校准NLL、ECE、Brier；修复/退化，精确双侧McNemar及20000次配对bootstrap差值区间；每模型Accuracy附Wilson区间。附两种模型的实际截断覆盖统计、训练耗时、显存及推理开销；不能把模型前向行数当作实测延迟。

净正收益可作为描述性结果；只有配对统计支持且披露开发集反复使用的限制时，才能称“本次开发对比显著”。单seed、历史模型选择和多轮开发探索均意味着它不是独立确认实验，不能直接宣称跨种子或测试分布稳定。即便oracle互补空间大，也不能保证固定平均能实现它。
