# 512 / 2048 上下文单种子完整对照

用户已批准 512 / 2048 同配方对照，并在工程短跑通过后指示“既然能接受住压力，那就试试吧，看看能不能有提升”。本轮正式训练一组 seed 42 配对；三种子六模型超出当前保守预算，不自动扩展。单种子结果是探索性证据，不能证明种子稳定性。

## 固定科学协议

- 两个模型均从冻结发布版 Laya 的同一完整 CE 权重初始化，编码器为 ModernBERT-large，保留原两层决策头，省去未参与 CE 的动作头。不得从短跑权重续训，不重置决策头。
- 固定 22100 梯度训练、400 校准、2500 开发划分及原标签。官方测试文本与逐条预测不读取。两种长度唯一科学差异是总输入上限 512 / 2048；固定模板占 46 token，超预算采用 token 级首尾拼接，训练和推理一致。
- seed 42，2 epochs，micro batch 8、grad accumulation 1；各 5526 更新、44200 样本暴露。编码器 LR 2.5e-5，头部 LR 1e-4，AdamW weight decay 0.01、梯度裁剪 1、余弦调度最小 LR 1e-6。CE、无标签平滑、相同样本和选项排列计划。
- 严格 CUDA FP32、关闭 AMP / TF32、梯度检查点，动态批内补齐，不另做分桶重排。每步损失、梯度、更新后参数必须有限；非有限值立即停止。
- 固定第 2 epoch 为最终模型，不按开发成绩挑 epoch、调整学习率、混入融合或清洗数据。两份最终权重、更新数、配对初始状态与两轮样本 / 选项计划核对后统一冻结，再进行开发评估。

## 准入、保存与恢复

保留旧科学源码不动。新增长度感知的 epoch 循环必须在 CPU 上验证：512 与原 CE 循环的参数、RNG、loss 完全一致；中断恢复与连续训练一致；2048 实际输入保留检查。启动正式训练前在完整模型、真实 2048 CUDA 输入上做连续 / 第 1 epoch 保存后重载的精确参数与 RNG 对比。准入失败不启动正式训练。

正式训练拆为四个 epoch 作业：512 e1、512 e2、2048 e1、2048 e2。每次保存完整 FP32 权重、优化器 / 调度器 / RNG、训练输入和更新审计、固定训练样本上的参考 logits、协议与可运行源码快照。先写临时目录，完成哈希后原子封存，显式提交持久化 Volume，再在独立进程严格重载、验证快照和 logits。第 2 epoch 必须从已验证第 1 epoch 恢复；这也检验实际恢复路径。

训练阶段仅用梯度训练样本作重载参照，不借用开发 / 校准指标。云端严格校验通过才继续下一阶段。本机自动接收逐轮封存包并进行整文件 SHA、独立 CPU 严格加载；本机离线时云端仍保留副本，明确标记本地未交付。接收器不得创建 GPU 任务，不覆盖云端原验证收据。平台抢占或失败不自动重试，保留已封存 epoch，后续仅能显式恢复。

## 评估与判读

统一冻结后，用各自输入长度的 400 校准样本拟合温度（范围 0.5 到 5），然后一次性输出两份开发预测。报告 Accuracy、Wilson 区间、Macro-F1、AUROC、原始 / 校准 NLL、ECE、Brier、配对修复 / 退化与精确 McNemar，以及样本条件配对 bootstrap 区间。分组统一按原 512 的 466 review-token 阈值；另列 2048 实际残余截断数。不把不同长度下各自的截断组当成同一批样本比较。开发集已被多轮使用，结果带有选择乐观性；不将置信区间解释为跨种子或未见测试保证。
