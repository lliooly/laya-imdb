# 原训练分区难例筛选与重采样准备

用户已批准从原训练分区筛选真正的语义难例，再设计受控重采样；沿用 seed 43 配对和逐轮检查点要求。本阶段只运行已有权重推理、候选排序和人工复核，不启动梯度训练。

## 固定方案

只读取冻结 train.jsonl，先校验文件 SHA、原训练 ID 顺序以及梯度/校准/验证 ID 互斥；验证只读 manifest ID，不读取验证正文。输出严格为原 22,100 梯度训练 ID，排除 400 校准及 2,500 开发验证 ID，不访问官方测试集。

已有 seed 43 基线、warmup 0.05 + label smoothing 0.05 最终两轮权重分别推理。维持训练时原前缀输入、512 总 tokens、原问题模板、batch=8、CUDA FP32、关闭 AMP 和 TF32、eval/no_grad。比较训练配置时不同时引入首尾窗口。核验模型、tokenizer 与 manifest SHA，保留每条输入哈希和有限 logits，输出拒绝覆盖。恢复本地已核验备份后使用临时远端权重，成功收回证据后删除本次恢复副本，本地备份保留。

完整训练池推理可以发现关键词未覆盖的模型困难，不只评估规则命中的 8,890 条。以两模型分歧、共同错、负标签对数概率损失与熵生成候选排序；原生校准温度只作诊断，采用原始 margin/NLL，避免不同温度改变候选排序的解释。明确这些都是已见训练样本上的统计，不是折外难度证据，不将低损失视为容易、高损失视为有用。

## 候选复核

保留既有规则及候选原样，按 ID、标签、正文 SHA 校验交叉连接。固定按类别与正负分层抽样、确定性 seed=20261011。互斥类别优先序为对象切换、低质量但享受、反讽代理、混合评价、未命中规则；每个类别每种标签抽 4 条模型优先候选和剩余池中随机 4 条，共最多 80 条。模型优先依次按共同错、分歧、平均原始 NLL 降序、ID 排序；类别不足时不跨层补齐。协议另存 review-protocol.json；样本数和抽样过程在生成候选审阅包之前锁定，不依据验证表现调整。审阅完整训练正文，标注同一作品的整体态度、评价对象、质量与享受、反讽、否定和标签张力，保存短证据。疑义标签隔离，不自动改标签或升权。

本阶段产物为有模型证据的候选清单及审阅报告。若不足以建立规模合理的语义池，则明确报告不足，不为了启动训练把规则并集当困难池。

## 后续训练设计边界

冻结候选与单一小幅采样强度，按 ID 去重并封顶；保持原每轮负类 11065、正类 11035 的采样量、总抽样 22100 次；batch=8、累积=1 时每轮 2763 次、两轮 5526 次优化更新，保持学习率计划及其他配置。记录每条暴露次数和覆盖，保留每轮检查点及完整开发验证；基线/重采样使用相同 seed 43，必要时再按配对 seed 42 复验。窗口与重采样各自做单因素对照。候选池确定后再保存具体训练设计，不把当前准备写成已训练结果。
