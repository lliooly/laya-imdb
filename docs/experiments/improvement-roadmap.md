# 后续改进路线

截至 2026-10-13，下面是基于已有实验的建议，尚未启动新训练。先完成结果归档与方案冻结，再执行新 run_id 的实验；不继续无依据搜索 R-Drop alpha、采样倍数或语义增强曝光比例。

## 1. 收尾现有证据

收回本轮语义 A/B/C 的完整预测、优化日志与六个逐轮权重，整文件 SHA 校验。重新核验 Mac 96.96% 候选权重和默认部署 checkpoint 的对应关系；默认推理入口仍指向历史一轮 checkpoint，最高成绩候选并未自动替换默认路径。确定最终参照、主指标和实验上限，避免把不同运行时的历史成绩混成配对收益。

## 2. 优先做首尾输入策略

已有四组固定权重的首尾窗口分别净改善 5、9、6、4 条，方向比当前重采样和语义增强更一致，但只有两个种子且受开发错题启发。先对 Mac 最高候选或新 strict 同期控制做固定权重诊断，保持总长 512、评论头233＋尾233，以及问题模板和标签不变；新输出不得覆盖历史导出。

通过输入一致性和 Mac 推理核对后，设计单因素「前缀训练／前缀推理」与「首尾训练／首尾推理」对照。冻结梯度、校准及开发 IDs、初始化权重、训练预算与 strict 设置；先 seed42 再按预声明结果规则决定 seed43。以最终保存权重的开发 Accuracy 为主，NLL、配对修正／退化和逐轮曲线为辅助。不能用最佳轮替换预声明最终轮，也不能只选一组有利结果。

这个训练适配尚未实现和验证。若要求比较纯训练因素，应另保留「前缀训练／首尾推理」作为固定权重诊断，避免同时改变训练和推理后错误归因。

## 3. 冻结 Laya 方法后迁移

为 ModernBERT-base 建立相同 512-token 预算、固定数据划分和可比训练预算的 CUDA CE 基线，再独立迁移有效输入策略。既有 94.64% 的 256-token MLX 三轮结果保留为历史参照，不能据此声称 Laya Head 的独立贡献。

然后做同预算 Laya-RLCD／CE 对照。已有 pilot 93.72%／93.52% 不代表全量损失优劣。迁移不以达到98%为硬门槛；每组记录参数量、训练耗时、推理成本、概率质量与 Accuracy。

## 4. 暂缓的方向

R-Drop、本次45条重采样与30来源增强未显示稳定 Accuracy 增益，暂不扩大搜索。30来源每个额外曝光约74次，小池结果不能排除更大、更多样且独立审核的语义增强可能有效；若重启，先分析实际新增／退化样本，再制定新池、新比例和未被筛选过的验证方案，不能沿开发错题反向改训练标签。

温度校准服务概率可信度，正温度不会改变 argmax；偏置收益不一致，不设默认偏置。更长输入、分块和集成属于额外预算方案，单独设计，不用它们掩盖首尾单因素比较。

## 5. 最终评估与交付

冻结一个最高准确率候选及一个高效单模型候选（可以同一模型），完成 Mac 部署核对，然后进行封存的官方测试。开发验证集反复参与选择，不能当作无偏最终成绩。IMDB 不直接代表真实场景表现；没有独立应用标注集就不报告应用准确率。最后整理 Word 报告、训练／测试视频和源码包，引用保留的失败实验及消融证据。
