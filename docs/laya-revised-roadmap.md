# IMDB 分类优化、方法迁移与 14 天开发计划

首次制定：2026-10-09。更新：2026-10-10。状态：用户已确认研究路线；具体训练参数由可行性检查和受控实验决定。

## 目标与已确认约束

- 作业评价重点：模型或方法创新性、分类准确率、报告质量。
- 主指标为分类准确率（Accuracy），目标是实际应用尽量达到 98%。开发期间仅用固定开发验证集衡量改进，方案冻结后用官方 25,000 条测试集检验最终效果。98% 属于研究目标，不是已达到的成绩或可保证的交付指标；测试集达到 98% 对应错误数不超过 500。
- IMDB 成绩不能直接代表真实应用准确率。若开展应用场景评估，另准备贴近使用场景、具有人工标签的独立评估集，不用于调参；没有该评估时只报告 IMDB 上的结果。
- 同时评价概率可信度：NLL、Brier、ECE、可靠性曲线及高置信度错误；温度校准不等于提升分类准确率。
- 训练使用 PyTorch/CUDA，按量计费；预算上限 200–250 元。原计划 RTX 4090 24GB，首台实租设备为 RTX 6000D 84GB，正式配置依据实际测速制定。
- 推理保留在 Apple Silicon Mac，首选 MLX FP16。
- 先优化 Laya-CE，再将有效方法迁移到 ModernBERT 和 Laya-RLCD，分别重新训练。按开发验证 Accuracy 选择最终方案，同时记录部署成本；保留其他实验用于论文比较。
- 保留最高准确率版和高效单模型版的交付方向，二者共享数据协议并分别记录成本；若同一单模型兼顾两项目标，可使用同一版本。集成属于可选扩展，不占用方法迁移的必要预算。
- 继续在现有目录工作，不创建 worktree、不切分支、不使用视觉伴侣。

## 现有证据与技术缺口

ModernBERT-base 在完整开发验证集准确率为 94.64%，Laya-CE 为 95.76%。Laya 当前验证错误 106/2,500；98% 对应最多 50 条错误，差距不是仅靠校准就能解决。

Laya 有约 4.21 亿参数，不能因 FP16 部署称其参数规模比 ModernBERT-base 更小。当前同权重 MLX FP16 与 MPS FP32 在 2,500 条验证集预测标签一致，后端速度对照已经完成；两模型之间统一端到端成本对照仍需补齐。

当前 `configs/laya-full-ce.json` 使用 MPS、FP32、1 轮、micro-batch 1、累积 8、总长度 512，400 条原训练样本仅作校准。当前训练主要调用上游训练器，没有精确断点恢复。入口接收 device 字段不代表 CUDA、AMP 或跨平台恢复已验证。

## 路线选择

执行顺序为“Laya-CE 优化 → 有效方法冻结 → ModernBERT / Laya-RLCD 迁移与对照 → 最终方案选择 → 部署和正式测试”。论文围绕方法改进及其迁移效果展开，先确认改动在 Laya-CE 上有效，再检验其在其他实验路线上的适用性。

98% 不作为迁移阶段的硬性门槛。达到目标或用完 Laya-CE 阶段的预定预算后，冻结当前最佳方法并推进迁移；未达到目标时如实记录，不无限追加搜索。

RLCD 是 Laya 的训练目标，不是独立编码器；对应实验路线称为 Laya-RLCD。ModernBERT 迁移以现有 base 为起点。迁移对象是适用的输入处理和训练方法，不直接移植 Laya 决策头、模型权重或整套最优超参数。

领域词表适配、大规模架构重做和蒸馏不列为必做项。Laya-RLCD 的同预算训练纳入迁移对照，规模由测速及剩余预算确定；若只能完成小规模对照，所有相关组使用一致样本预算，并明确标为 pilot，不宣称完成全量比较。

## 阶段 A：数据、错误与 CUDA 闭环

1. 固定现有数据清单、原始权重和 tokenizer；将当前 Laya-CE 记录为不可覆盖的历史参照。
2. 分析完整验证错误和长度分层：截断、否定、混合情感、讽刺、疑似标签歧义。分析只用于选择研究方向，不手工修改验证标签或为特定样本定制规则。
3. CUDA 小批量前向、反向、保存重载和离线运行检查；检测非有限损失、设备错误和显存不足并停止该运行。
4. 核实上游 AMP 的实际 dtype 和实现，再选择支持的混合精度；先验证数值与训练稳定性，不直接把训练精度变化计作方法收益。
5. 测参数更新耗时、完整流程耗时、峰值显存及样本吞吐；据此制定正式实验配置与费用估算。
6. CUDA 导出权重回传 Mac，核对输入、logits/概率偏差、标签一致率及整体验证指标。转换或加载失败时保留原权重，修复后再验，不以格式转换成功代替效果验证。

输出：CUDA 可行性与测速记录、跨平台核对报告、成本估算。未经测量不承诺 batch 或每轮耗时。

## 阶段 B：Laya-CE 优化与方法冻结

研究线一为训练策略：以可复现 CUDA 参照为起点，有限筛选编码器/决策头学习率、warmup、轮数和正则化。一次对照明确改变因素；筛选不能使用不一致样本预算却宣称某策略因果有效。

研究线二为长文本信息利用：优先比较相同总 token 预算下的前缀与首尾保留；若长评论错误证据充分，再评估更长输入或分块聚合。更长输入的结果同时报告额外计算成本，不能归为纯截断策略收益。先核实模型及决策头实际长度限制。

只把完整验证上最有希望的一到两个改进推进正式验证，并逐项消融，确认各改动的贡献。小样本 pilot 只用于筛选可行性，不据此宣布最终收益。不提前指定最优学习率、训练轮数或策略。

以完整开发验证 Accuracy 为第一选择指标；准确率相同时，优先验证 NLL 更低的方案，仍相同时优先端到端推理成本更低的方案。冻结有效改动、配置、checkpoint 和数据 ID 后再迁移，不根据迁移结果反复修改已冻结的 Laya-CE 方法。

输出：Laya-CE 参照与改进结果、关键消融、冻结方法清单，以及未达到 98% 时的实际成绩和限制。

## 阶段 C：方法迁移与受控比较

每条路线分别训练参照组和改进组，使用相同的数据划分、梯度训练/校准 ID、评估脚本及该路线内的样本预算。历史结果保留为参照；新增实验使用新 run_id，不覆盖原输出。

| 路线 | 参照组 | 改进组 | 比较目的 |
|---|---|---|---|
| Laya-CE | 当前平台上的受控 CE 参照 | 冻结的有效方法 | 验证主要改进及其消融 |
| ModernBERT-base | 当前平台上的普通分类头参照 | 适用方法迁移后重新训练 | 检验不同模型上的收益 |
| Laya-RLCD | 与 CE 使用同一初始权重、相同预算的 RLCD 参照 | 适用方法迁移后重新训练 | 检验不同训练目标下的收益 |

ModernBERT 历史基线使用 MLX、256 token、3 轮且未保留训练校准集，与现有 Laya 的条件不同。若改用 PyTorch/CUDA，先完成模型、训练、保存重载和 Mac 推理核对，并重建同平台参照；框架与精度迁移不计作方法收益。迁移组的可选超参数调整使用事先限定的筛选预算，并记录各模型实际搜索次数。

通用输入策略和训练策略可以迁移；编码器与决策头学习率分组、选项顺序增强等依赖结构的改动，只在目标模型具有对应结构时应用。记录未适用的组件，不能把部分迁移表述为完整方法复现。

路线内尽量保持除研究因素外的条件一致。跨模型比较同时披露参数量、实际影评 token 预算、训练轮数、更新次数、校准方式和计算成本；不能仅凭模型间 Accuracy 差异证明某个结构更优。CE/RLCD 的损失对照保持其他条件一致。

输出：各路线参照/改进结果、逐样本预测、方法适用性记录和统一比较表。无提升或失败的运行保留配置、日志与状态，不删除或包装为成功结果。

## 阶段 D：稳定性与最终方案选择

- 对最终方法移除主要改动，保持其他条件一致，区分各组件贡献。
- 优先对最终单模型及必要参照使用 42/43/44 三个训练种子，保持数据与校准 ID 不变；预算不足时明确缩减并报告限制，不虚构稳定性。
- 根据完整开发验证 Accuracy 选择最终方案，不根据正式测试结果换模型。多种子结果齐备时比较验证 Accuracy 均值并报告标准差；仅单种子时明确选择证据的限制。准确率相同的候选按阶段 B 的规则比较。
- 根据验证预测的错误互补性，评估 2–3 个已训练成员的集成；成员、权重和聚合规则只在开发阶段决定，不遍历大量组合。
- 高效版选择单模型，最高准确率版可采用集成。若集成收益不足以支持其成本，可以让二者使用同一个单模型。
- 报告单模型/集成 Accuracy、Macro-F1、概率指标和成本；不将采用他人模型本身表述为自主架构创新。

## 阶段 E：可信概率与最终测试

固定训练 22,500、验证 2,500、官方测试 25,000。继续从原训练划分固定保留 400 条校准样本，22,100 条用于梯度训练。校准样本不能参与梯度更新，校准温度或集成后校准仅在该保留集拟合；该集不能同时被包装为独立最终效果证据。

开发验证集已被多次使用，相关成绩与配对检验只能作为开发证据。报告历史模型比较时说明模型规模、文本预算与训练预算差异。

在接触正式测试前，保存两版模型的 checkpoint/hash、输入策略、集成规则、校准参数、推理精度和评估脚本，形成冻结清单。两版可在同一次最终评估阶段测试，但不得根据测试成绩改变成员或参数。未达到 98% 时如实报告，不反复测试直到达到目标。

最终报告同时给出准确率置信区间、Macro-F1、混淆矩阵、NLL/Brier/ECE、高置信度错误比例及其定义，区分有限测试样本的不确定性与跨训练种子的变动。

## 阶段 F：Mac 部署、论文图表与交付

优先保持 MLX FP16，补齐同硬件同样本的基线与最终两版端到端测速。分别报告模型加载、预热、分词、驻留推理 P50/P95、批量吞吐和峰值内存；跨框架内存统计口径不一致时分列说明。

集成版的全部成员与聚合成本必须计入测速；只有确实运行通过的版本才能称为 Mac 可部署。量化仅在时间允许且兼容时尝试，并重新验证效果。

保留全部参照、改进、消融及迁移实验的必要权重、配置、训练日志、指标和逐样本预测。最终部署选中的方案，其他有效实验用于论文比较；未部署不等于删除实验。模型权重仍不提交到 Git。

论文图表包括各路线参照/改进 Accuracy 与 Macro-F1、关键消融、训练和验证曲线、长短评论分层、校准曲线，以及 Accuracy 与延迟/吞吐/内存/训练费用的比较。多种子误差条与测试准确率置信区间分别标注；历史耗时口径不同的结果单列，缺失指标不补造。

交付 Word 报告（题目、摘要、引言、方法、实验、结论、参考文献），源码压缩包、训练视频和测试视频。两个视频分别不超过 5 分钟，保留真实过程并标注剪辑/加速。源码包包含锁定依赖、配置、复现命令、模型获取/导出说明，排除缓存和无关运行目录。

候选题目：面向 IMDB 情感分类的微调优化、方法迁移与高效部署。题目随最终有效方法调整，不预写未经实验支持的创新结论。

## 相对 14 天排期与预算

从路线批准后起算；阶段可按实际耗时调整，最后三天优先保障交付。

| 时间 | 工作与退出条件 |
|---|---|
| 第 1–2 天 | 错误分析、CUDA 可行性与训练/导出/MLX 闭环，得到费用估算 |
| 第 3–5 天 | Laya-CE 有限筛选、完整验证和关键消融，冻结有效方法 |
| 第 6–8 天 | ModernBERT 与 Laya-RLCD 参照/迁移训练，完成必要稳定性验证 |
| 第 9 天 | 根据验证 Accuracy 选择最终方案，完成校准并冻结候选 |
| 第 10–11 天 | Mac 性能优化与核对，冻结部署精度后最终测试 |
| 第 12–14 天 | 报告定稿、视频、压缩包与干净环境复现 |

预算按 250 元硬上限规划：CUDA 闭环最多 20 元，Laya-CE 筛选、主实验与关键消融最多 100 元，ModernBERT / Laya-RLCD 迁移对照及必要复验最多 80 元，余下 50 元作为失败重跑、存储和收尾缓冲。若实际预算采用 200 元，则减少筛选规模并保留收尾缓冲，不降低数据隔离要求。集成只在必要实验完成后有剩余预算时开展。

每次付费训练前记录时价、预计开机时间、累计费用与剩余额度。分析和写报告尽量在本地完成，训练后关闭实例；精确恢复能力未实现验证前，不把旧入口当作可恢复任务。不得因 98% 目标无限增加搜索次数或突破预算。
