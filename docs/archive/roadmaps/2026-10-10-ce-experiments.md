# 完整 CUDA 参照之后的 CE 对照

初始计划日期：2026-10-10；更新日期：2026-10-11。首轮 CUDA 参照、Mac 两轮对照与独立 RTX 4090 两轮参照已完成。下文保留原 RTX 6000D 两组后续配置的计划，它们没有执行；RTX 4090 使用单独配置和 run_id。

## 当前下一组：标签平滑与 warmup

RTX 4090 两轮参照耗时约 42 分钟，实际保存权重重载 Accuracy 为 95.88%，低于 Mac 两轮最佳的 96.96%。103 条错误中 84 条未截断、19 条截断。相同 4090 配置上的标签平滑 0.05 和 5% warmup 独立对照已完成，Accuracy 分别为 96.16% 和 96.32%。两组均未超过 Mac 最佳；单种子增幅尚不足以证明稳定收益。

新配置、调度定义、仅对梯度训练应用平滑的规则、冒烟与正式命令见[独立对照设计与执行说明](../../superpowers/specs/2026-10-11-laya-ce-regularization-design.md)。完成证据和错误分析见 [4090 独立对照分析](../../../reports/rtx4090-regularization-completed-v1/REPORT.md)。根据两组各有净收益且错误不完全重合，下一轮组合 5% warmup 与平滑 0.05，组合两轮正式训练及保存权重完整验证已完成，Accuracy 96.44%，尚未超过历史 Mac 最佳。旧配置沿用原训练路径，新权重 Mac 核对尚未进行。

## Mac 实际执行结果

用户在 Mac 上执行 `laya-mac-ce-epochs2-fp32.json` 与 `laya-mac-ce-epochs2-lr06-fp32.json`，使用 MPS FP32、micro-batch 1、梯度累积 8、评估 batch 1。两组均从原始权重开始，各训练两轮。

保存权重以 MPS FP32 重载后，原学习率组 Accuracy 为 96.96%，较低学习率组为 96.12%。当前最佳候选为原学习率两轮组，76 条错误，距离该验证集 98% 还需净改正 26 条。[分析报告](../../../reports/laya-mac-ce-comparison-v1/REPORT.md)单独记录配对结果、推理核对和剩余错误。下面保留原始 CUDA 计划及当时的误差分析，不将其算力配置或费用估算用于 Mac 实际耗时。

实际保存权重的 CUDA 开发验证 Accuracy 为 96.28%，错误 93/2,500；距离 98% 还需净改正 43 条。错误中 72 条未截断、21 条截断。因此先做训练策略对照，再研究相同 token 预算的首尾保留。即使理想化地改正全部 21 条截断错误且无新增错误，也只有 97.12%，不能只靠长文本路线承诺达到 98%。

## 已准备的训练配置

所有组使用同一原始 Laya 权重、22100/400/2500 数据 ID、512 总 token、FP32、micro-batch 8、累积 1、seed 42。校准 ID 不做梯度训练。修改学习率与轮数的实验继续调用同一上游 cosine 调度策略。

| 组 | epochs | encoder/head 初始学习率 | 配置 | 状态 |
|---|---:|---|---|---|
| CUDA 参照 | 1 | 2.5e-5 / 1e-4 | `laya-cuda-reference-ce-fp32.json` | 已完成，96.28% |
| 两轮 | 2 | 2.5e-5 / 1e-4 | `laya-cuda-ce-epochs2-fp32.json` | 已准备，未运行 |
| 两轮、较低学习率 | 2 | 1.5e-5 / 6e-5 | `laya-cuda-ce-epochs2-lr06-fp32.json` | 已准备，未运行 |

两轮组相对参照只改变 epochs，cosine 的总步数随之改变；它不是“第一轮轨迹完全相同后再追加一轮”。学习率组相对两轮组只改变两组初始学习率，按同一 0.6 比例降低；保持 min_lr、weight_decay、loss、输入和数据预算一致。

按首轮 16.8 分钟的完整耗时粗估，两轮约 34 分钟；仅供排程，真实记录为准。每组进程上限 75 分钟，按截图单价 6.46 元/小时计算，进程时段上限约 8.08 元；另有传输/开机时间。完成这两组后检查边际收益，再决定下一组，不无条件消耗整个 CE 预算。

## 后续输入与调度策略

首尾保留优先采用约 2:1 的头/尾 token 分配，始终保持总输入 512 token 和相同问题模板。需要从完整 state token 中取尾部，不能从已经截断的 512 个 token 中再取“尾部”。训练与 Mac 推理必须实现同一策略，在配置中记录策略与预算，并通过 CUDA/MLX 全验证输入哈希检查后再比较。

首尾组与冻结的前缀训练策略使用相同轮数、学习率、数据 ID 和总 token 预算。更长输入/分块属于另一个计算预算的实验，不与该组混为同一因素。

上游 0.4.1 没有 warmup 字段。项目现已通过顶层 `optimization` 和独立适配器准备 5% warmup 对照，不向上游 `TrainConfig` 添加未知字段；CUDA 冒烟与正式 warmup 训练已完成，保存权重重载的完整开发验证 Accuracy 为 96.32%。调度定义与验证步骤见上面的独立对照说明。

## 选择与复验

以完整开发验证 Accuracy 排序，相同则比较校准后 NLL，再比较部署成本。先比较实际保存权重；候选模型必须在 Mac 上核对后端表现。有效候选再按预算做 seed 43/44 复验，报告均值、标准差和搜索次数。所有配置使用独立 run_id，保留失败与退步结果，不改变验证标签或样本。

历史 MPS 与当前 CUDA 的配对结果为改正 28 条、退步 15 条，净改正 13 条；精确双侧 McNemar p≈0.066。该比较还改变了平台和 micro-batch 分组，不能宣称已证明方法创新或在 0.05 水平显著提升。

达到目标或完成限定的 CE 筛选后，按已确认路线冻结有效方法并迁移到 ModernBERT-base / Laya-RLCD。官方测试集继续封存；98% 是研究目标，不是迁移硬性门槛。

## 后续：R-Drop 单因素验证

组合相对单独 warmup 仅净增 3 条正确。下一轮保持组合配置，只增加双前向一致性损失 alpha=1，不遍历更多平滑和升温比例。数学、隔离边界、CPU/CUDA 准入及余额门槛见 [R-Drop 设计](../../superpowers/specs/2026-10-11-laya-ce-rdrop-design.md)。正式 batch=8 冒烟及 39 项本地与远端 CPU 测试通过。正式两轮及完整保存权重验证已于 16:51 完成，Accuracy 96.08%，低于组合参照 96.44%，不替换最佳模型，也不自动追加 alpha 搜索。结果见 [完成分析](../../../reports/rtx4090-rdrop-completed-v1/REPORT.md)。证据见 [R-Drop 准入记录](../../../reports/rtx4090-rdrop-preparation-v1/REPORT.md)。
