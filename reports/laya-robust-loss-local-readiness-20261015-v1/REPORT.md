# 混合鲁棒损失与权重交付门禁：本地验收报告

日期：2026-10-15。用户已批准设计。状态：**实现及本地验证完成；23 项测试通过；真实 CUDA 与 SSH 回传准入尚未执行。没有启动新正式训练。**

## 1. 已实现的行为

| 单元 | 实现 | 验收结果 |
| --- | --- | --- |
| 固定损失 | CE 控制与 0.5 CE + 0.5 GCE(q=0.7)，只接收两槽、未平滑 one-hot 标签 | 自动微分符合预定梯度乘数；极端 logits 有限，选项置换不改变损失 |
| 可恢复训练 | 显式保留 AdamW、余弦调度、CPU / CUDA / Python / NumPy RNG、选项 RNG、游标和历史 | CPU 小模型从 epoch-001 恢复，与连续训练最终参数、完整输入和更新日志完全一致 |
| 输入与数值审计 | 固定配对输入计划，逐条 token / 标签 / 选项记录，逐次更新记录与有限值保护 | CE 新循环与固定旧循环的损失、最终参数和 Torch RNG 完全一致；两损失输入 SHA 相同、最终参数不同 |
| 文件交付 | 不可变清单、逐文件大小 / SHA、前缀校验后续传、原子落盘、独立进程 CPU strict load | 小模型真实文件完成传输与加载；仅收到摘要或传输命令退出成功不会产生有效收据 |
| 进度门禁 | epoch 收据、冻结收据、最终评估结果收据 | 第一 epoch 回调失败后没有第二 epoch 更新；旧收据、缺文件和坏文件均无法通过 |
| 恢复与幂等 | 本地持久化收据后发送 ACK；确认丢失可重发 | 已有本地有效权重和收据保留，不要求重训；恢复时校验协议、模型和日志前缀 |
| 远端编排 | 四个 CUDA 短跑准入、三种子六次正式训练、共同冻结后开发评估 | 入口和门禁已实现；正式入口自身检查准入，不依赖操作者一定使用 study 编排 |

生产流程拒绝 `local-test` 收据，要求 SSH 交付并保留本地 100 GiB 空间检查。这样本地文件测试、或服务器上第二个目录中的复制，不能直接作为正式准入证据。

## 2. 测试覆盖与结果

全部使用锁定本地依赖，在 CPU 上执行。共 **23 项，0 failure，0 error**：

- 新训练单元 6 项：梯度公式、极端值 / 非法输入、旧 CE 循环回归、完整 epoch 恢复、失败不推进、两臂输入一致而参数变化。
- 新交付单元 9 项：真实独立加载、重复 ACK、真实字节流中断及坏前缀恢复、缺失 / 坏 SHA / 过期收据、磁盘写入失败、接收端缺失、ACK 丢失后重发、路径限制、不可加载检查点、冻结及评估回传，以及 SSH 远端程序的本地执行检查。一个测试可能覆盖多个故障场景。
- 既有头部单元 8 项：模型 / 初始化 / checkpoint / 输入计划 / 温度与指标回归。

故障注入会故意产生校验异常或子进程加载异常；这些异常被测试验证为阻止收据，不是测试失败。磁盘错误通过注入写入失败模拟，其余文件复制、SHA、模型加载、断流后剩余字节和恢复训练均实际执行。

交付测试中的 400 条校准和 2500 条评估记录是小模型的**合成测试数据**，不是读取真实开发或官方测试后得到的实验结果。SSH 远端标准库程序也是在本机直接执行，未连接网络；不能据此宣称新服务器认证、网络吞吐或大模型交付已经通过。

可复查 `test-results.txt` 的逐项输出与 [summary.json](summary.json) 的环境、测试数、耗时和日志 SHA。测试小模型文件保存在临时目录并在测试后清理，不是新增正式模型交付。

## 4. 下一台服务器必须通过的准入

1. 新主机可用，OpenSSH 能非交互执行远端命令，认证和 host key 已核验；本地接收器先启动。
2. 实测完整模型 / 恢复包的传输、落盘、SHA 和 CPU strict load，记录收据耗时；两端满足 100 GiB 空闲要求。
3. CE、混合损失各两次 32 次更新。各臂第二次在 epoch-001 交付后退出再恢复，必须与连续短跑的逐更新记录、输入 SHA 和最终模型 SHA 一致。
4. 准入通过后，才允许三种子六次正式训练；六个最终模型都已回传冻结后，才允许开发评估。评估预测另行回传后再做统计分析。

正式六模型的权重及第一 epoch 优化器约 37.6 GiB；四个完整参数准入模型另约 25.1 GiB，**总计约 62.7 GiB，另加源码、配置和审计**。传输与本地加载会延长租用时间，不能只按上轮约 4.2 小时的正式计算耗时估预算。接收器记录实际包大小与接收耗时，供新主机准入后估算。

## 5. 当前限制

- CPU 小模型通过不等于实际 Laya 的 CUDA 运行、恢复或跨平台加载通过；这些必须实测。
- 本地 ACK 通过 SSH 返回，证明接收器已检查并落盘；不是独立可信第三方签名或恶意主机威胁模型。
- 第一 epoch 完成前的远端故障仍可能丢失中途进度；文件尚未完整封装时不能冒充有效恢复点。
- 没有新训练收益数据，不能把鲁棒损失描述成已提升 Accuracy；原标签与文本冲突候选也未升级成已证实错标。
