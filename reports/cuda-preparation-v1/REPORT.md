# CUDA 训练链路验证与测速

日期：2026-10-10。GPU：RTX 6000D，84 GB 标称显存。仅使用冻结训练/开发验证数据；未上传或评估官方测试文本。

## 已完成的验证

- 初次上传的 77 个文件均在服务器核对 SHA-256。代码、原始 Laya 权重、train/validation 与既有锁文件一致。
- 独立环境安装锁定的 `torch==2.14.1`、`laya==0.4.1`、`transformers==4.57.6` 等依赖。CUDA 构建为 13.0，驱动为 595.71.05；实际前向和反向可执行。
- 官方 PyPI 下载过慢，改用腾讯镜像；先 `uv export --locked` 导出固定版本和哈希，再 `uv pip sync --require-hashes` 安装。随后 `uv sync --offline --locked --extra laya` 通过。未修改 `uv.lock`。
- 服务器使用镜像自带 Python 3.12.3，满足项目 `>=3.12,<3.13`。命令显式指定该解释器；与 Mac 的 3.12.14 补丁版本差异保留在环境记录中。
- FP32 v2、v3：6 条梯度训练、2 条校准、4 条独立验证，3 次优化器更新。编码器与决策头均实际更新，损失、梯度、参数有限，FP16 保存权重严格重载匹配，4 条重载预测保持一致。
- v3 使用新增的 CUDA 非有限值保护；出现非有限损失或梯度时中止，防止异常更新继续推进。保护不改变有限值条件下的训练数学，CPU 回归测试验证了这一点。
- v2 权重回传 Mac，SHA-256 匹配，MLX FP16 的 4 条输入哈希及标签与 CUDA 完全一致；最大绝对概率差 `3.301599138305633e-06`，低于预先指定的 0.01 工程阈值。

`readiness.json` 是训练前的时间点记录，其中 `cuda_training_ready=false` 不改写；后续实际运行、数值审计与 Mac 核对共同提供新的验证证据。4 条样本仅验证工程链路，不能用其准确率声称研究收益，也不代表完整验证集后端一致。

## FP16 发现的问题

当前上游 `amp=true` 显式使用 FP16 autocast 与 CUDA GradScaler。它不是 BF16 训练。

无保护的 FP16 v1 在第三个梯度窗口出现非有限值：实际优化器更新 2 次，调度器却推进 3 次。训练入口报告完成，但数值审计判为失败。加入保护后，FP16 v2 在该窗口及时中止，优化器与调度器均保持 2 次，不产生正式可选模型。

现阶段采用 FP32 正式参照，FP16 不通过训练准入。后续若调整混合精度或损失缩放，必须另用新 run_id、重新验证，不能将失败运行删除或当作准确率比较对象。

## 性能测量

8 条真实训练评论均能填满 512 token；仅用于速度测量，均来自训练划分。启用编码器/决策头梯度检查点，关闭 TF32。每个 batch 预热 2 次、测量 5 次；包含同步前向、反向、梯度裁剪、AdamW，输入已预置 GPU。学习率为 0；参数数值哈希在运行前后相同，不保存研究 checkpoint。

## 保留的失败记录

FP32 v1 因审计脚本用 FP32 `linspace` 抽样大张量端点而越界。该脚本问题已改为整数索引计算，并加入超过 FP32 精确整数范围的回归测试；v2、v3 均通过。失败不是 GPU 不支持模型的证据。

测速前两次也保留了日志：首次未过滤 collate 的列表元数据；第二次的全 state_dict 字节哈希不一致。最终比较命名参数数值，规范化正负零、排除运行时 buffer，前后哈希相同。三个尝试不用于准确率或方法收益比较。

## 下一步与边界

`configs/laya-cuda-reference-ce-fp32.json` 已通过预检：22,100 条梯度训练、400 条校准、2,500 条验证，1 轮，micro-batch 8、累积 1。有效 batch 8、更新预算、学习率和输入预算与历史 CE 配置一致，但平台与随机 dropout 的分组不同；CUDA 与 MPS 差异不能直接归因于方法创新。

首轮完整 CUDA 参照已完成，运行编号 `laya-cuda-reference-ce-l512-s42-fp32-v1`。实际完整耗时 1007.20 秒，保存权重的开发验证 Accuracy 为 96.28%。单次进程上限为 2,700 秒，按截图 6.46 元/小时估算；实际训练进程时段约 1.81 元，实例开机、传输和存储另计。进程结束不等于实例自动关机。

实际保存的 FP16 权重在 CUDA 以 FP32 重载，导出全部验证预测；完整权重回传 Mac 并核对 SHA-256。MLX FP16 的 2,500 条输入和预测标签全部一致，最大绝对概率差 0.00610005，低于预先指定的 0.01 工程阈值。详见[完整运行报告](../laya-cuda-reference-ce-l512-s42-fp32-v1/REPORT.md)。已通知用户可关闭实例，98% 仍为目标。
