# 48 条候选的本地复核补充与暴露计划

本补充承接冻结 v2 清单及独立复核，记录边界样本、适用范围和实际采样计划。历史报告、48 条冻结清单、原数据及标签均保持原样；本次只做本地演算，未连接远端或训练。现有采样适配器已经支持该 48 条清单，不能再将适配器描述为尚未实现。CUDA 冒烟及正式训练是否完成，需由对应运行记录证明。

三条尚未达成新共识。因此本补充生成的是当前冻结 48 条的条件性计划，不将其声明为语义准入已全部通过。若后续隔离或移出任何条目，需新建候选版本、哈希和暴露计划，再检查配置及适配器对新版本的支持；不能只改计划里的候选数量。

## 适用范围与处理强度

48 条中组合配置独错 39 条（81.25%）、基线独错 5 条、共同错 4 条。该池面向 warmup=0.05、label_smoothing=0.05 的组合配置优化；训练内错误不是折外难度证据，不能由此声称适用于所有配置或预言验证收益。两遍原审阅由同一 AI 会话完成，标签及模型判断可见。

沿用既定 1.5 倍、两轮、seed=43 的同标签固定次数替换，不提高处理强度。候选各出现 3 次，48 条同标签非候选各出现 1 次，其余 22,004 条各出现 2 次。额外候选暴露为 48/44,200，约 0.10860%；这属于小处理强度对照，无改善不能直接否定难例重采样。后续改变倍数需要训练前另存预声明，不能看到验证表现后追调。

## 新计划及核验

[resampling-exposure-plan.json](resampling-exposure-plan.json) 与 [control-exposure-plan.json](control-exposure-plan.json) 绑定现有冻结清单 SHA-256：`51684631a97f2e4ff7cfaad5739918a84137c78c38e3885a9aadce31c21d9c38`。用当前 `scripts/laya_resampling.py` 的真实 `make_plan` 演算，随后按上游 seed+epoch 规则排序。保存逐轮全部有序 ID、顺序哈希、逐 ID 暴露次数及被替换 ID；历史 28 条计划保持原样。

核验要求：每轮 22,100 条，负类 11,065、正类 11,035；batch=8、grad_accum=1 时每轮 2,763 次、两轮 5,526 次预期更新；两轮暴露 44,200，全部 22,100 个原梯度 ID 至少出现一次。候选不进入校准或开发分区，源标签、正文哈希与冻结记录一致。控制组每个 ID 两次；处理组每轮单 ID 最多两次。17 负/31 正的候选分布通过同标签替换保留全训练类别暴露，不补未经审阅的样本。

这些更新数为计划推导，实际优化更新和逐轮权重仍需训练日志核验。正式配对沿用原始初始化、前缀 512 tokens、FP32、非有限值保护、两轮检查点及最终轮完整开发 Accuracy 主比较；窗口变化不混入该因素。机器已关机，本补充不启动云端流程。

## 复现与审计

```bash
uv run --locked --offline python reports/laya-train-hardcase-review-v2-supplement-v1/build_exposure_plan.py
```

生成 [summary.json](summary.json)、两组暴露计划、[exposure-counts.csv](exposure-counts.csv) 及 [provenance.json](provenance.json)。脚本拒绝覆盖不同内容，冻结池、原报告和历史计划哈希纳入记录。现有执行文档仍作为流程参考；本补充中的三条待复核状态是执行前需解决的语义问题，本次不新增训练授权。
