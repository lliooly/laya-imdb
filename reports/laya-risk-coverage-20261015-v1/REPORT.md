## 1. 结论与下一步决策

**选择性分类在这批开发集上有明确的实用价值；融合相对单模型的稳定优势尚未得到确认。**

1. 按置信度保留前 90% 的样本，两种方案均为 **2224/2250 = 98.84%**，Wilson 95% 区间为 **[98.31%, 99.21%]**。这描述的是保留样本，不是全覆盖准确率。
2. 保留前 80% 时，融合为 **1991/2000 = 99.55%**，单模型为 **1990/2000 = 99.50%**。融合领先 **0.05 pp**，配对 bootstrap 95% 区间为 **[−0.10, +0.25] pp**，仍包含零。
3. 融合的 AURC 为 **0.00340446**，单模型为 **0.00406628**。差值（融合减单模型）为 **−0.00066182**，95% 区间为 **[−0.00189796, +0.00016105]**。点估计约下降 16.28%，但该结果不足以确认总体 AURC 改善。
4. 用原校准集的 90% 覆盖目标确定融合阈值 **0.9703539312**，在开发集上的实际覆盖率为 **90.68%**，保留准确率为 **98.81%**。这说明固定阈值可执行，但覆盖率不会自动等于校准目标。
5. 总体 80% 覆盖率时，融合只保留 **71.25%** 的截断样本，未截断样本保留 **81.70%**。保留集合的难度和组成已经改变，不能把选择性成绩全部解释成模型能力改善。

因此，Z2 的开发集报告任务可以收尾。现阶段保留单模型作为成本参照，冻结融合作为候选，不凭这些结果扩大训练或宣称融合稳定胜出。后续先完成位置明确的 L1 冻结表示探针；若要采用拒答策略，先明确覆盖率或人工复核预算，再冻结一套阈值规则，并在新的独立样本上评估。

## 3. 指标与不确定性方法

### 3.1 覆盖率、风险与 AURC

每种方案独立按最大类别概率降序排列；同分时保持原文件顺序。对前 `k` 条计算：

```text
coverage(k) = k / 2500
selective_accuracy(k) = 前 k 条中的正确数 / k
risk(k) = 1 − selective_accuracy(k)
AURC = mean(risk(k), k = 1, …, 2500)
```

AURC 越低越好，单位为错误率的小数。这里采用所有非空前缀风险的算术平均，不使用其他积分插值或归一化变体。AURC 差乘以 100 可表示平均风险的百分点变化，但不等同于某个固定覆盖率上的准确率增益。

100%、90%、80%、70%、50% 五个覆盖点沿用此前已经展示的结果。本次在 bootstrap 计算前固定分析协议，但开发集和这些覆盖点已经被看过，**不是预注册的独立确认实验**。完整离散曲线保留全部 2500 个点，置信区间网格为 1% 至 100%、步长 1%。

### 3.2 配对 bootstrap

- 主分析：按真实类别分层，每次分别从 1250 条负类和 1250 条正类中有放回抽样，保持原开发集的均衡设计。
- 同一轮对两种方案使用**同一批抽样 ID 及其重复次数**；两种方案分别重新形成自己的置信度顺序和保留集合。并非固定原来的前 k 条后只重采样该子集。
- 计算上先分别建立两种方案的排序，再按每轮抽样次数展开，等价于对每轮多重集合分别重排；已用 30 轮抽样、两种方案逐一与显式排序核对。
- 主分析 **20,000 轮**，随机种子 **20261015**；敏感性分析另做 **20,000 轮普通配对 IID bootstrap**，种子 **20261016**。
- 区间取 bootstrap 分布的 2.5% 和 97.5% 分位数，使用 NumPy 默认线性分位数插值。准确率差统一为“融合减单模型”；AURC 差同向，负数有利于融合。
- 所有覆盖点及图中阴影均为**逐点 95% 区间**，不是整条曲线的同时置信带；不进行从曲线上寻找显著区间的推断。

不能把两种方案在 80% 或 90% 覆盖率下的保留集合当成完全相同的样本直接做 McNemar 检验。两者 90% 覆盖时各保留 2250 条，交集为 **2224 条**；80% 时各保留 2000 条，交集为 **1955 条**。90% 交集数恰与正确数相同只是数值巧合。

### 3.3 区间能覆盖什么

表中单项准确率给出 **Wilson 95% 二项近似区间**，便于结合正确数解释；绝对准确率的重排 bootstrap 区间也已保存到 `summary.json`。固定覆盖点的选样存在样本间依赖，Wilson 在这里是描述性的近似，不能当作有限样本风险保证。

配对 bootstrap 则估计**固定权重、固定融合参数、固定排序规则下，开发集样本变化所带来的不确定性**。它不覆盖训练 seed 方差、400 条校准集的拟合与阈值选择误差、开发集反复使用和方案筛选、标注偏差或部署分布变化。校准温度、融合系数和阈值均未在 bootstrap 中重拟合。各方案和各覆盖点的区间高度相关，不能通过比较两条独立区间是否重叠判断差异。

极少错误的区间尤其需要谨慎。例如 50% 覆盖率时融合只错 1 条；bootstrap 可能抽不到这条错误，绝对准确率区间上端达到 100%。这不意味着总体零风险。完整曲线低覆盖段若没有观察到错误，非参数 bootstrap 也无法生成未观察到的错误类型。

## 6. 只用校准集选择阈值后的开发集表现

### 6.1 规则

在原 400 条校准集上，对每个方案分别计算置信度。目标覆盖率为 `c` 时，以第 `400×c` 大的置信度为阈值，保留 `confidence >= threshold` 的样本；100% 目标统一用 0.5。规则只使用校准置信度，不依据开发集标签或开发集分位数调整阈值。此次 90%、80%、70%、50% 目标在校准集分别保留 360、320、280、200 条，没有跨边界同分导致的超额保留。

这些阈值是**本次新增的校准集阈值诊断**，没有在原实验开始前预注册，也没有自动写入生产配置。校准数据已参与温度或融合拟合，开发集也已多次参与研究；这里不是独立认证。下表区间仅条件于这批校准数据和已定阈值，没有量化换一批校准数据后的阈值波动。

## 7. 成本、后续优先级与使用纪律

### 7.1 成本与目标

本次只有 CPU 概率统计，新增模型 forward 为 **0**。若未来按当前门控规则执行两模型融合，在相同开发集长度分布下，需要 **5814 次样本级 forward**：两模型各处理 2500 条 head，再各对 407 条长文本处理 head_tail。单模型直接使用 head_tail 需 2500 次样本级 forward，融合约为其 **2.33 倍**。这是输入次数核算，不是实测延迟、显存或金额，尚未计入批处理与部署优化。

拒答发生在这些概率产生之后，不会自动省掉已执行的推理。是否值得采用融合，应同时看独立数据上的风险—覆盖收益、推理代价，以及被拒绝样本的人工复核成本。

**全覆盖研究目标仍然独立存在**：融合全覆盖只有 96.96%，拒绝 10% 后的 98.84% 不替代全覆盖 98% 的目标，也不应成为迁移其他模型的新增硬性门槛。

| 3 | 对训练错题补审候选开展独立核验 | 使用上一份 94 条合并台账，优先 58 条标签冲突候选；不自动翻标签、不由本报告启动重训 |
| 4 | 若准备启用拒答，确定实际约束并冻结一套规则 | 明确覆盖率 / 人工预算、截断组最低服务覆盖、阈值精度及概率生成版本，再安排新的独立数据验证 |
| 5 | 只有需要证明跨训练稳定性时，再做多个匹配 seed 的同期对照 | 每个 seed 使用相同输入和比较口径，单独报告训练变化与样本不确定性；本报告的 bootstrap 不替代此步骤 |

独立阈值验证应同时报告实际覆盖率、保留准确率及区间、截断组保留率和成本。若目标是“以指定置信度控制错误率”，需另定带风险控制保证的校准流程及相应假设，不能给当前分位数阈值附加该保证。官方测试集继续封存，不为本项分析追加多轮阈值搜索或反复查看。
